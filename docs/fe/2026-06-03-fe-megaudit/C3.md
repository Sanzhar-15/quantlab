# FE Megaudit — Lane C3 (Cross-Repo + Wire Protocol)

Scope: IDE-side Quantbook FE contract fidelity against the current napi/Rust surface in the sibling engine checkout at `../quantlab-quantbook/quantbook-engine`. Engine internals are referenced only to identify the emitted wire shape/error codes.

## HIGH

None.

## MEDIUM

### MEDIUM-1: Required engine protocol fields are modeled and accepted as optional

- **Type:** Real FE defect / guard weakness. Current engine sends the fields, but the IDE would accept a malformed or skewed real napi response without failing loud.
- **IDE:** `extensions/quantlab/src/quantbook/types.ts:317`, `extensions/quantlab/src/quantbook/types.ts:330`, `extensions/quantlab/src/quantbook/types.ts:456`, `extensions/quantlab/src/quantbook/types.ts:1703`; `extensions/quantlab/src/quantbook/session.ts:1110`; `extensions/quantlab/src/quantbook/cellGrid/cellGridLogic.ts:1157`
- **Engine:** `../quantlab-quantbook/quantbook-engine/crates/ql-bindings-node/src/lib.rs:953`, `../quantlab-quantbook/quantbook-engine/crates/ql-bindings-node/src/lib.rs:961`, `../quantlab-quantbook/quantbook-engine/crates/ql-bindings-node/src/lib.rs:1087`, `../quantlab-quantbook/quantbook-engine/crates/ql-bindings-node/src/lib.rs:1121`, `../quantlab-quantbook/quantbook-engine/crates/ql-bindings-node/src/lib.rs:5160`
- **Failure:** `WorkbookSnapshotJson.version`, `WorkbookSnapshotJson.schemaVersion`, `WorkbookSnapshotDeltaJson.schemaVersion`, and `RangeResultJson.schemaVersion` are required by the engine DTOs, but the TS mirrors make them optional and `assertSupportedSchemaVersion(undefined)` deliberately no-ops. `acquireWorkbookSnapshotViaDelta` then caches `seed.version` even when it is `undefined`, turning a missing version token into repeated full reseeds instead of a protocol error. A stale/broken native binary that omits these fields can therefore render or limp along without the intended `unsupported_schema_version`/version-token failure.
- **Minimal fix:** Split fixture-only permissiveness from real napi ingestion. Make the production DTO mirrors required, or add strict boundary helpers for `session.snapshot()`, `session.snapshotDelta()`, and `queryRange()` that require `schemaVersion === QUANTBOOK_SCHEMA_VERSION` and require `version instanceof Uint8Array`/`Buffer` where applicable. Keep relaxed fixture types/builders only in tests.

### MEDIUM-2: `errorReply` delivery rejection is logged but not user-visible

- **Type:** Real defect now in the dispatch error path.
- **IDE:** `extensions/quantlab/src/quantbook/cellGrid/cellGridLogic.ts:393`, `extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:398`, `extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:406`
- **Failure:** Engine/validation failures are correctly parsed into `errorReply` in `dispatchIncomingMessage`, and the normal `postMessage(...).then(delivered => !delivered)` path falls back to `showWarningMessage`. The rejection path only does `console.error('[cellGrid] errorReply postMessage rejected:', err)`. If the webview channel rejects while carrying a formula/bind/recalc error, the user sees no warning, violating No-Fallbacks for the end-to-end error path.
- **Minimal fix:** In the rejection callback, log the rejection and also call `vscode.window.showWarningMessage` with the same `[code] message` used by the `!delivered` branch.

## LOW

### LOW-1: Malformed snapshot/delta anomalies are silently dropped instead of failing loud

- **Type:** Forward-work / readiness gap. Current engine should not emit these shapes, but they are protocol-drift cases and the FE currently masks them.
- **IDE:** `extensions/quantlab/src/quantbook/cellGrid/cellGridLogic.ts:737`, `extensions/quantlab/src/quantbook/cellGrid/cellGridLogic.ts:1064`, `extensions/quantlab/src/quantbook/cellGrid/cellGridLogic.ts:1076`
- **Failure:** `extractSheetSnapshot` silently `continue`s when a cell has neither `value` nor `formula`. `mergeWorkbookDelta` silently skips `changedCells` and `removedCells` for unknown sheet ids. Both comments say the engine should not produce these states, but if the wire contract drifts or a real engine bug emits them, the IDE hides the mismatch and renders a divergent workbook.
- **Minimal fix:** Treat impossible wire shapes as boundary errors: throw a `[bad_argument]`/`[unsupported_schema_version]`-prefixed error with sheet/row/col details, or force a loud full-resync path for unknown-sheet deltas rather than `continue`.
