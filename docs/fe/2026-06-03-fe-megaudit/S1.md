**Files audited:** `webview/sheets-webview/canvasGrid.ts`, `webview/sheets-webview/gridLayout.ts`,
`webview/sheets-webview/index.ts` (draw/scroll wiring), `webview/sheets-webview/cellRender.ts`,
`webview/sheets-webview/sheets-webview.css`.

## MEDIUM findings

### M1 — No-Fallbacks: `readPalette()` silently swallows missing `--vscode-*` CSS vars

**File:line:** `canvasGrid.ts:258–272`

**Failure:** `readPalette()` uses a local helper `v(name, fallback)` that returns a hardcoded
colour string whenever `getComputedStyle(document.body).getPropertyValue(name)` returns an empty
string. All seven palette entries have silent fallbacks:

```ts
const v = (name: string, fallback: string): string => {
    const raw = cs.getPropertyValue(name).trim();
    return raw.length > 0 ? raw : fallback;  // <-- silent swallow
};
```

If VS Code fails to inject any of these CSS variables (e.g., corrupted theme, wrong webview CSP,
unexpected execution context), the renderer silently paints with hardcoded dark-mode colours.
The user sees wrong colours; there is no log, no throw, no signal. This violates the project
No-Fallbacks hard rule: *"no `value || default` patterns that mask missing config or broken state"*.

**Minimal fix:** Replace silent return with a `console.error` before falling back, so the missing
variable is visible in the webview DevTools console:

```ts
const v = (name: string, fallback: string): string => {
    const raw = cs.getPropertyValue(name).trim();
    if (raw.length === 0) {
        console.error('[sheets-webview] CSS var missing:', name, '-- falling back to', fallback);
        return fallback;
    }
    return raw;
};
```

### M2 — No-Fallbacks: `readFonts()` silently falls back to `'sans-serif'` on missing `--vscode-font-family`

**File:line:** `canvasGrid.ts:276`

**Failure:**

```ts
const family = getComputedStyle(document.body).getPropertyValue('--vscode-font-family').trim() || 'sans-serif';
```

Same pattern as M1: if `--vscode-font-family` is not injected, the grid renders with a default
`sans-serif` font without any signal. This also invalidates the measure cache silently (the cached
widths would be for the real font, but paint happens with `sans-serif`), causing truncation to
misfire on the wrong widths — text could overflow or be clipped too aggressively. Violates
No-Fallbacks.

Note: the `|| 'sans-serif'` also fires when the property value is the empty string (correct) but
also when it is `'0'` (falsy-coercion on non-empty strings is not an issue here since `''` is
already caught by `.trim()`). The real concern is the silent fallback.

**Minimal fix:**

```ts
const raw = getComputedStyle(document.body).getPropertyValue('--vscode-font-family').trim();
if (raw.length === 0) {
    console.error('[sheets-webview] --vscode-font-family not injected; falling back to sans-serif');
}
const family = raw.length > 0 ? raw : 'sans-serif';
```

## LOW findings

### L1 — No-Fallbacks: `resolveDpr()` uses `|| 1` to mask absent `devicePixelRatio`

**File:line:** `canvasGrid.ts:67`

```ts
return Math.min(2, Math.max(1, Math.ceil(window.devicePixelRatio || 1)));
```

`window.devicePixelRatio` is always defined (and positive) in VS Code's Electron-hosted webview.
The `|| 1` guard silently hides the case where it is `0` or `undefined` (which would indicate a
very broken host environment). Not a practical risk in production, but violates the rule.

**Minimal fix:** Remove the fallback; if `devicePixelRatio` is falsy, throw:

```ts
const dpr = window.devicePixelRatio;
if (!dpr || dpr <= 0) {
    throw new Error('sheets-webview: window.devicePixelRatio unavailable');
}
return Math.min(2, Math.max(1, Math.ceil(dpr)));
```

### L2 — No-Fallbacks: `typeof ResizeObserver !== 'undefined'` guard silently skips canvas resize

**File:line:** `index.ts:291–293`

```ts
if (typeof ResizeObserver !== 'undefined') {
    new ResizeObserver(() => redraw()).observe(viewportEl);
}
```

If `ResizeObserver` is not available (extremely unlikely in VS Code's Chromium webview), the canvas
is never resized when the viewport changes size. The canvas remains at its initial 1×1 default (or
whatever its first size was), producing a blank or clipped render. The failure is completely silent.
Violates No-Fallbacks.

**Minimal fix:** Remove the guard; throw if unavailable:

```ts
if (typeof ResizeObserver === 'undefined') {
    throw new Error('sheets-webview: ResizeObserver unavailable');
}
new ResizeObserver(() => redraw()).observe(viewportEl);
```

### L3 — Scroll handler fires `redraw()` synchronously on every scroll event (no rAF throttle)

**File:line:** `index.ts:288`

```ts
viewportEl.addEventListener('scroll', redraw);
```

`redraw()` calls `renderer.resize()` + a full `renderer.draw()` (which iterates the visible entry
window, makes `measureText` calls, and issues multiple `fillRect`/`fillText`/`stroke` calls).
With fast trackpad or wheel scroll, the browser can fire dozens of scroll events per animation
frame. Each fires a synchronous full repaint. For the current bounded list-view (entries in the
hundreds), this is unlikely to produce visible stutter. But it is not throttled, and as entry count
grows toward the FE-2 target it will become a problem.

**Minimal fix** (correctness-safe, zero-risk):

```ts
let rafId = 0;
viewportEl.addEventListener('scroll', () => {
    if (rafId) return;
    rafId = requestAnimationFrame(() => { rafId = 0; redraw(); });
});
```

### L4 — DPR change on monitor switch not detected until next resize event

**File:line:** `canvasGrid.ts:89–90` (inside `resize()`), `index.ts:291`

`resolveDpr()` is only called inside `resize()`, which is only called from `redraw()`. `redraw()`
is only triggered by scroll, ResizeObserver, theme change, or a new render snapshot. Moving the
VS Code window from a 1× to a 2× monitor (or changing system scaling) does not trigger a resize
event, so `dpr` stays stale and the canvas backing store is not re-sized. The result is a blurry
canvas on the new display until any resize occurs.

**Minimal fix:** Add a `matchMedia` listener for DPR changes (standard pattern):

```ts
// In index.ts, after ResizeObserver setup:
const dprQuery = window.matchMedia(`(resolution: ${window.devicePixelRatio}dppx)`);
dprQuery.addEventListener('change', () => redraw());
```

Note: this requires re-creating the query each time it fires (the resolution changes). Alternatively,
use a `window.devicePixelRatio` change watcher loop (the standard approach).

### L5 — Overlay editor left-padding (6 px) does not match canvas `CELL_PAD` (8 px): 2 px text-start misalignment

**File:line:** `sheets-webview.css:69` (`padding: 2px 6px`) vs `canvasGrid.ts:28` (`const CELL_PAD = 8`)

When the user opens a cell for editing, the overlay `<input>` appears over the canvas Value cell.
The canvas draws cell text at `x + CELL_PAD = columnX(2) + 8` (i.e., 152 px from content origin).
The input's text starts at `columnX(2) + 6 = 150 px` (CSS `padding-left: 6px`).
The 2 px gap makes the text in the editor appear 2 px to the left of the canvas position, causing a
visible jump on edit entry.

**Minimal fix:** Align the CSS padding to CELL_PAD. Either change `canvasGrid.ts:28` to `CELL_PAD = 6`, or change `sheets-webview.css:69` to `padding: 2px 8px`. Prefer the latter (the 8 px canvas pad reads better for the wider Value column):

```css
.cell-edit-input {
    padding: 2px 8px;  /* was 2px 6px -- align with canvas CELL_PAD=8 */
}
```

## Positive observations (no issues)

- **Coordinate model is correct.** Concrete verification at `scrollTop=75, scrollLeft=50`: the CSS
  `transform: translate(scrollLeft, scrollTop)` on the absolute-positioned canvas exactly
  counteracts the scroll displacement, giving `canvas.getBoundingClientRect()` = viewport origin.
  `ev.clientX - rect.left` = viewport-local X. `hitTestViewport` correctly rejects the sticky
  header in local coords before adding the scroll offset (the note in `gridLayout.ts:114–117` is
  accurate). `beginEdit` positions the overlay `<input>` in content coords, which scroll
  automatically with the container. All confirmed with concrete numbers.

- **HiDPI backing store is correct.** `resize()` sets `canvas.width = round(cssWidth * dpr)`,
  `canvas.style.width = cssWidth + 'px'`, then `draw()` calls `ctx.setTransform(dpr, 0, 0, dpr,
  0, 0)`. All draw calls are in CSS coords; the transform scales them to physical pixels. The
  context state is reset by `setTransform` at the top of every frame, not accumulated. When
  `canvas.width/height` changes (size change), the context state is reset by the browser; `draw()`
  immediately re-applies `setTransform`. Correct.

- **Header sticky paint is correct.** The canvas is drawn with `scrollTop/scrollLeft` passed as
  parameters but the header is always drawn at `y=0` in local (viewport-origin) coordinates.
  Overscan rows with negative `localY` are drawn first; `drawHeader` is drawn last (on top), with
  an opaque background base layer, correctly covering any overscan bleed. The double `fillRect`
  (background then headerBg) correctly handles translucent `headerBg` colours.

- **Measure cache consistency.** `ctx.font` is set to `bodyFont` before the row loop in `draw()`,
  is not changed inside `ctx.save()/restore()` in `drawRow()`, and `drawHeader()` restores
  `bodyFont` at its end. All `measure()` calls use `bodyFont`. Cache keys are the text string only,
  which is safe because the font is invariant between `refreshTheme()` calls. Cache is cleared on
  `refreshTheme()`.

- **Border line crispness math.** `lineY = Math.round(localY + ROW_HEIGHT) - 0.5` in CSS coords.
  At `dpr=2`, this maps to `(2*Math.round(...) - 1)` physical pixels, which is an odd integer —
  the stroke centre is at a pixel-grid half-integer in physical space, giving a crisp 1-physical-px
  line. Same for column separators. Correct.

- **Empty-state rendering.** When `entries.length === 0` (including before first snapshot), the
  header is drawn and the message `(empty -- no PutValue ops on this sheet)` is placed at
  `(CELL_PAD, HEADER_HEIGHT + ROW_HEIGHT/2)` with `textBaseline='middle'`. Correct and graceful.

- **No per-frame `getComputedStyle`.** `readPalette()` and `readFonts()` (which call
  `getComputedStyle`) are only invoked from `refreshTheme()`, which is called on snapshot arrival
  and on body-class `MutationObserver` (theme changes). Not called per scroll frame. No per-frame
  style recalc cliff.

- **`truncateToWidth` binary search.** Correct for all boundary cases: empty string, text that
  fits, text where even the ellipsis does not fit (returns `''`), single character. Binary search
  is `O(log n)` in string length with `n` `measure()` calls (cache-backed).

- **`computeVisibleRowRange` scroll-shrink clamping** (`cellRender.ts:83`). The clamp of
  `firstVisible` to `totalRows-1` correctly handles stale large `scrollTop` when content shrinks
  (sheet switch, undo, delete). Documented + tested.
