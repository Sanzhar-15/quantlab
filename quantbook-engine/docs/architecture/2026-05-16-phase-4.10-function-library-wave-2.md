## 3. Batch 1 (4.10.A) — Logical fillins

### 3.1 Functions

#### `IFS(test1, value1, test2, value2, ..., [test_default, value_default])`

Multi-condition selector. Returns `valueK` for the first true `testK`. Excel canon:
- Variadic, even count of args (pairs of test+value).
- No `else` arg: if no test passes, return `#N/A`.
- Errors in tests propagate.
- Empty input → `#VALUE!`.
- Odd arg count → `#N/A` (matches Excel; the trailing unpaired arg is ignored as missing-value rather than syntax error).

```rust
pub fn ifs(args: &[Value]) -> Value {
    if args.is_empty() { return Value::Error(ErrorValue::Value); }
    let mut i = 0;
    while i + 1 < args.len() {
        match &args[i] {
            Value::Error(e) => return Value::Error(*e),
            other => match coercion::to_logical(other) {
                Ok(true) => return args[i + 1].clone(),
                Ok(false) => {}
                Err(e) => return Value::Error(e),
            },
        }
        i += 2;
    }
    Value::Error(ErrorValue::Na)
}
```

#### `IFNA(value, fallback)`

Like `IFERROR` but only catches `#N/A`. Other errors propagate.

```rust
pub fn ifna(args: &[Value]) -> Value {
    if args.len() != 2 { return Value::Error(ErrorValue::Value); }
    match &args[0] {
        Value::Error(ErrorValue::Na) => args[1].clone(),
        v => v.clone(),
    }
}
```

#### `XOR(args...)`

Variadic logical XOR — true iff an odd number of args are true. Mirrors `AND`/`OR` argument handling: skip blanks, coerce non-bool via `to_logical`, propagate errors, require ≥1 non-blank.

```rust
pub fn xor(args: &[Value]) -> Value {
    if args.is_empty() { return Value::Error(ErrorValue::Value); }
    let mut count = 0u64;
    let mut any_non_blank = false;
    for v in args {
        match v {
            Value::Error(e) => return Value::Error(*e),
            Value::Blank => {}
            other => {
                any_non_blank = true;
                match coercion::to_logical(other) {
                    Ok(b) => if b { count += 1 },
                    Err(e) => return Value::Error(e),
                }
            }
        }
    }
    if !any_non_blank { return Value::Error(ErrorValue::Value); }
    Value::Boolean(count % 2 == 1)
}
```

#### `SWITCH(expression, value1, result1, value2, result2, ..., [default])`

Matches `expression` against `valueK` (case-insensitive text equality, numeric equality, bool equality). Returns `resultK` on first match. Optional trailing `default` (odd arg count after expression).

- Variadic ≥3 args (1 expression + at least 1 value+result pair).
- Even count after expression → no default → `#N/A` on no match.
- Odd count after expression → last arg is default.
- Errors in `expression` propagate. Errors in `valueK` skip that pair (NOT propagate — matches Excel SWITCH canon, unlike IFS which propagates test errors).

```rust
pub fn switch(args: &[Value]) -> Value {
    if args.len() < 3 { return Value::Error(ErrorValue::Value); }
    let expr = &args[0];
    if let Value::Error(e) = expr { return Value::Error(*e); }
    let mut i = 1;
    while i + 1 < args.len() {
        let v = &args[i];
        let r = &args[i + 1];
        if !matches!(v, Value::Error(_)) && values_match_for_switch(expr, v) {
            return r.clone();
        }
        i += 2;
    }
    // i == args.len() - 1 → unpaired trailing arg is the default.
    if i < args.len() { return args[i].clone(); }
    Value::Error(ErrorValue::Na)
}
```

`values_match_for_switch`: case-insensitive String equality, Number/Bool/Blank exact, Error never matches. Open question for Codex pre-review: does Excel allow Number↔String cross-type match (e.g., `SWITCH(1, "1", "match")`)? IronCalc reference says NO (strict type); HyperFormula says YES (coerce). Default to strict.

### 3.3 Test plan

Per function, the existing `scalar_fns::tests` module pattern:
- Happy path (2-3 cases).
- Error propagation (test in IFS, expression in SWITCH).
- Edge cases:
  - IFS: no match → #N/A; odd arg count → #N/A; first match wins.
  - IFNA: #N/A → fallback; other errors → propagate; non-error → value.
  - XOR: 0 / 1 / 2 / 3 trues; all blanks → #VALUE!.
  - SWITCH: no match + no default → #N/A; default branch; first match wins; type-strict equality.

Target: ≥6 tests per function, ≥24 total. Workspace test count: 2643 → ~2667.

Plus 1 e2e in `workbook_runtime::tests` exercising each through the full `set_formula` path.

## 4. Batches 4.10.B-H — brief outlines

### 4.10.B — Conditional aggregate fillins (MINIFS, MAXIFS, COUNTBLANK)

Mirror W5-55 SUMIFS/COUNTIFS pattern. All `RangeAwareFn`. COUNTBLANK is simpler (single range, count blanks). MINIFS/MAXIFS share W5-55's criterion-predicate suite + W5-61 wildcards. **W5-60 KNOWN DIVERGENCE** applies (sum_range vs range shape) — surface in matrix Notes.

### 4.10.C — Stats `*A` variants (AVERAGEA, MAXA, MINA)

`*A` variants coerce text → 0, bool → 0/1, error propagates. Distinct from base AVERAGE/MAX/MIN which skip text+bool. RangeAwareFn.

### 4.10.D — Info fillins (NA, ERROR.TYPE, ISFORMULA, TYPE)

- `NA()` — trivial: returns `Value::Error(ErrorValue::Na)`. Scalar, no args (or 0 args).
- `ERROR.TYPE(value)` — 1=#NULL!, 2=#DIV/0!, 3=#VALUE!, 4=#REF!, 5=#NAME?, 6=#NUM!, 7=#N/A. Non-error → #N/A.
- `TYPE(value)` — 1=number, 2=text, 4=bool, 16=error, 64=array. Scalar.
- `ISFORMULA(reference)` — ContextAwareFn; needs access to `Workbook::formula_at(s,r,c)`. Reference arg semantic is tricky: today's binder passes a Value (the cell's evaluated content), not a reference handle. **Open question**: do we need a parser/binder change to preserve the reference? Probably YES — bundle with a small AST tweak. May defer to a follow-up batch if AST changes balloon scope.

### 4.10.E — Math combinatorics + sum variants

- `FACT(n)` — factorial; n<0 → #NUM!; n>170 → #NUM! (overflow).
- `FACTDOUBLE(n)` — double factorial.
- `COMBIN(n,k)`, `COMBINA(n,k)` — combinations (no rep / with rep).
- `PERMUT(n,k)`, `PERMUTATIONA(n,k)` — permutations.
- `SUMSQ`, `SUMX2MY2`, `SUMX2PY2`, `SUMXMY2` — variadic sum-of-squares + cross products. RangeAwareFn for the multi-range pair variants.

### 4.10.F — Text utility fillins

- `TEXTJOIN(delim, ignore_empty, args...)` — RangeAwareFn; supersedes CONCAT for the delimiter-controlled case.
- `VALUE(text)` — text → number, locale-aware (decimal separator). ContextAwareFn (uses locale).
- `CHAR(code)`, `CODE(text)`, `UNICODE(text)`, `UNICHAR(code)` — codepoint round-trip.
- `FIXED(number, decimals, no_commas)` — number → text with thousands grouping. Locale-aware.
- `DOLLAR(number, decimals)` — currency text. Locale-aware.

### 4.10.G — Financial basics

`PMT / FV / PV / NPER / RATE` — TVM family. Closed-form for PMT/FV/PV/NPER; RATE is iterative (Newton-Raphson with bounded iterations).

`NPV / IRR` — RangeAwareFn over cash-flow range. IRR is iterative.

Open question: which Excel sign convention to follow (inflows positive vs outflows positive)? Match Excel canon (outflows negative, signs preserved).

### 4.10.H — Lookup expansion

The big one. **XLOOKUP** is the modern replacement for VLOOKUP/HLOOKUP/INDEX+MATCH. Supports 2-way lookup, multiple match modes (exact / next-larger / next-smaller / wildcard / regex-ish), search direction (first/last). RangeAwareFn.

**XMATCH** — like XLOOKUP but returns position.

**OFFSET / INDIRECT** — return reference handles, not values. **Significant architecture impact**: currently the engine doesn't have a "reference value" tier. May require a new `Value::Reference` variant or a binder-level rewrite. **DEFER to a separate design doc** — these are not 4.10 batches, they're their own mini-phase.

**ADDRESS** — coord → A1 text. Scalar; depends on locale (R1C1 mode) — ContextAwareFn.

**COLUMN / ROW / COLUMNS / ROWS** — return position. ContextAwareFn (need owning-cell address for the 0-arg form).

**FORMULATEXT(reference)** — return formula text at reference. Same reference-tier issue as ISFORMULA — bundle with 4.10.D's ISFORMULA design.

## 5. Cross-cutting infra additions

- **Reference-tier value** (4.10.D ISFORMULA, 4.10.H OFFSET/INDIRECT/COLUMN/ROW): probably needs `FnArg::Reference { sheet, row, col }` or similar. Bundle with 4.10.D as a small AST tweak OR with 4.10.H as a larger phase. Decide based on Codex pre-review.
- **Locale-aware VALUE / FIXED / DOLLAR** (4.10.F): use existing `EvalContext.locale` (already wired in W5-153). No new infra.
- **Iterative-numeric helpers** (4.10.G RATE, IRR): a new `num_iter` module with Newton-Raphson + bounded iterations + tolerance configurable via a registry constant. Reusable.

## 7. Open questions for Codex pre-review

1. **SWITCH type-strictness** (§ 3.1) — IronCalc strict vs HyperFormula lenient. Default strict; verify with reference reads.
2. **Reference-tier value** (§ 5) — design footprint. Bundle 4.10.D ISFORMULA or break out as its own design doc?
3. **OFFSET/INDIRECT scope** (§ 4.10.H) — these are semantically problematic for the calcgraph (dynamic dep targets). May need explicit deferral or a constrained subset (compile-time-resolvable args only).
4. **Financial canon coverage** (§ 4.10.G) — Excel's PMT formula has multiple sign-convention modes (`type` arg = 0 or 1 for begin/end of period). Confirm we match Excel exactly.
5. **Wave-2 budget realism** — 8 batches × ~1 commit avg ≈ 8 commits, but 4.10.E (10 functions) and 4.10.H (10 functions) are large; realistic span is 10-12 commits across 2-3 sessions. Confirm or adjust.
