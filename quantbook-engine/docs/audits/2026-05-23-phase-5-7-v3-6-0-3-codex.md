# Phase 5.7 V3.6.0.3 D2 Codex Audit

Audit date: 2026-05-23  
Scope: session-wide `RegisterFormat` `FormatTable` cache plus required `WorkbookSnapshotJson.formats` field  
Engine target: `ffa598a1c15` lineage, audited on current `feat/quantbook-engine` worktree  
IDE target: `b159c899359` lineage, audited against `feat/visualise-v1` files

## Verdict

PASS-WITH-FINDINGS

No HIGH correctness failure was confirmed. The suspected `RegisterFormat` undo stale-cache failure is refuted by the current undo/redo fallback behavior and by a compiled probe. The shipped surface does, however, have MEDIUM contract issues around nondeterministic `formats` array order, unguarded Builtin `RegisterFormat` replay, and public cache/Workbook divergence for invalid same-id/different-string format registrations.

## Summary

- `Op::RegisterFormat` now participates in the session cache walker via `CacheEffect::RegisterFormat` at `crates/ql-collab/src/session.rs:186`, `crates/ql-collab/src/session.rs:1097`, and `crates/ql-collab/src/session.rs:1211`.
- `format_table_cache` is initialized and rebuilt in the same walker discipline as `last_snapshot` and `removed_sheets` at `crates/ql-collab/src/session.rs:831`, `crates/ql-collab/src/session.rs:893`, and `crates/ql-collab/src/session.rs:1477`.
- `undo()` and `redo()` correctly treat empty/non-cell undo metadata as a full-cache rebuild trigger at `crates/ql-collab/src/session.rs:2887` and `crates/ql-collab/src/session.rs:2954`.
- `workbook_snapshot` populates `formats` from rebuilt `Workbook` state, not from `CollabSession::format_table_cache_iter`, at `crates/ql-bindings-node/src/lib.rs:1690`.
- The new required TS field is present in `extensions/quantlab/src/quantbook/types.ts:183` and covered by shape smoke tests at `extensions/quantlab/test/quantbook-roundtrip.test.ts:5611`.

## MEDIUM findings

1. MEDIUM-1: `WorkbookSnapshotJson.formats` order is nondeterministic across equivalent workbook states.

   Scope: napi snapshot contract and IDE consumers.

   Evidence:

   - `workbook_snapshot` rebuilds a fresh `Workbook` and directly collects `workbook.formats().iter()` into the JSON array at `crates/ql-bindings-node/src/lib.rs:1568` and `crates/ql-bindings-node/src/lib.rs:1690`.
   - `FormatTable::iter` is a raw `HashMap` iteration at `crates/ql-storage/src/format.rs:539`.
   - The binding docs claim the order is "stable for a given version + workbook state" at `crates/ql-bindings-node/src/lib.rs:625`; the TS contract repeats the same claim at `extensions/quantlab/src/quantbook/types.ts:191`.
   - A compiled probe over eight fresh `Workbook::new().formats().iter()` calls emitted different Builtin orders in the same process.

   Impact:

   A consumer that hashes or stringifies `workbookSnapshot()` can observe changed JSON with unchanged workbook content. This is worse than a merely "unsorted" array because `workbook_snapshot` rebuilds the backing `HashMap` per call, so order can shift between consecutive snapshots.

   Suggested closure:

   Sort `formats` before returning from `workbook_snapshot`, preferably by a stable `FormatId` key such as `(Builtin, id)` before `(Custom, peer, counter)`, or by an `Ord` implementation on `FormatId` if the project already has one. Then update the Rust and TS docs to make the deterministic order part of the napi contract.

2. MEDIUM-2: Builtin `Op::RegisterFormat` is accepted into both the session cache and authoritative `Workbook`, despite docs saying Builtins are not op-log registrations.

   Scope: malformed or hostile peer op logs; `.qbook` / merge replay semantics.

   Evidence:

   - The cache walker converts any `FormatIdWire` with `to_storage()` and does not reject `FormatIdWire::Builtin` at `crates/ql-collab/src/session.rs:1097`.
   - `apply_cache_effect` blindly inserts the id/string pair at `crates/ql-collab/src/session.rs:1211`.
   - Replay routes `Op::RegisterFormat` into `FormatTable::register_at` at `crates/ql-oplog/src/replay.rs:707`.
   - `FormatTable::register_at` rejects out-of-range Builtins but accepts in-range Builtins that are not already present at `crates/ql-storage/src/format.rs:416`.
   - A compiled probe appended `Op::RegisterFormat { id: Builtin(99), string: "evil-builtin" }`; the session cache contained `Builtin(99) -> "evil-builtin"` and `rebuild_workbook().formats().lookup(Builtin(99))` returned the same string.
   - The session docs claim the cache holds "ONLY Custom format registrations" and that Builtins never appear in the op log at `crates/ql-collab/src/session.rs:765` and `crates/ql-collab/src/session.rs:1340`.

   Impact:

   A peer can define a Builtin id that was not preloaded by `FormatTable::new()`, and `workbookSnapshot().formats` can surface it as if it were authoritative. That breaks the documented separation between static Builtins and collaborative Custom registrations.

   Suggested closure:

   Reject `FormatIdWire::Builtin` in collaborative `Op::RegisterFormat` replay and cache walking, or split trusted import-time Builtin backfill from collaborative register ops. If lazy Builtin registration is required for import fidelity, validate it against canonical Builtin definitions instead of accepting arbitrary strings.

3. MEDIUM-3: Same-id/different-string `RegisterFormat` conflicts leave the public session cache with a value even though authoritative Workbook replay rejects the log.

   Scope: public cache accessor and future delta consumers.

   Evidence:

   - `CacheEffect::RegisterFormat` documentation explicitly says the cache is "blind LWW" at `crates/ql-collab/src/session.rs:195`.
   - `format_table_cache_iter` is public at `crates/ql-collab/src/session.rs:1349`.
   - `rebuild_workbook` drops partial state and returns replay errors at `crates/ql-collab/src/session.rs:1809`.
   - A compiled three-peer probe created concurrent `RegisterFormat` ops with the same Custom id and different strings. After merge, all session caches converged to `B_FMT`, but `rebuild_workbook()` returned an error on all peers due to the `FormatTable` collision.

   Impact:

   Current napi `workbook_snapshot` avoids this by reading the authoritative `Workbook`, but the public cache accessor can expose a "valid-looking" format value for a replay-invalid log. The comments at `crates/ql-collab/src/session.rs:761` and `crates/ql-collab/src/session.rs:1353` already point at future delta consumers; those consumers could mistakenly treat the cache as authoritative.

   Suggested closure:

   Mirror `FormatTable::register_at` collision semantics in the cache walker. On same-id/different-string, mark the cache invalid or trigger the same replay error path rather than exposing an LWW entry. If that is too much for V3.6, keep `format_table_cache_iter` private/test-only until the cache carries a validity bit.

## LOW findings

1. LOW-1: Required additive `formats` is a shape break for exact-key/hash consumers.

   Scope: IDE and external napi consumers.

   Evidence:

   - `WorkbookSnapshotJson.formats` is required in Rust at `crates/ql-bindings-node/src/lib.rs:615` and in TypeScript at `extensions/quantlab/src/quantbook/types.ts:189`.
   - Existing exact-key tests were updated to include `formats` at `extensions/quantlab/test/quantbook-roundtrip.test.ts:4393` and `extensions/quantlab/test/quantbook-roundtrip.test.ts:5674`.

   Impact:

   Destructuring consumers continue to work, but consumers using `Object.keys`, exact deep equality, `JSON.stringify(snapshot)`, or snapshot-hash stability will see a breaking shape change. I did not find active IDE source consumers doing this outside tests, but this should be called out in the consumer contract.

   Suggested closure:

   Document `formats` as a required V3.6.0.3 field with explicit migration guidance for exact-shape consumers. If backwards compatibility is required across package versions, consider an optional field for one release window or a versioned snapshot contract.

2. LOW-2: Regression coverage is narrow for the changed walker discipline.

   Scope: ql-collab and IDE tests.

   Evidence:

   - The two new ql-collab tests cover append and forced rebuild only at `crates/ql-collab/src/session.rs:3919` and `crates/ql-collab/src/session.rs:3965`.
   - The IDE tests cover required shape and Builtin presence smoke cases at `extensions/quantlab/test/quantbook-roundtrip.test.ts:5611`.

   Missing coverage:

   - undo/redo of `Op::RegisterFormat`;
   - `merge_bytes` path for format registrations;
   - Builtin `Op::RegisterFormat` rejection or documented acceptance;
   - same-id/different-string conflict behavior;
   - `.qbook` round-trip preserving or rebuilding the session cache;
   - mixed cell-keyed ops plus `RegisterFormat` in the same undo group or log replay.

   Suggested closure:

   Promote the probes below into targeted regression tests once the desired Builtin/conflict behavior is decided.

3. LOW-3: `invalidate_cell` now allocates a throwaway format cache per call.

   Scope: performance lifecycle.

   Evidence:

   - `invalidate_cell` creates `local_format_cache: HashMap<FormatId, Arc<str>>` at `crates/ql-collab/src/session.rs:1601`.
   - `RegisterFormat` is skipped for per-cell invalidation at `crates/ql-collab/src/session.rs:1614`, so the map remains a defensive parameter placeholder.

   Impact:

   At current V3.6 usage this is negligible next to the O(N) log walk. If V3.7+ moves to frequent per-op invalidation, the extra allocation becomes avoidable noise.

   Suggested closure:

   Either pass a reusable scratch cache, make the format-cache argument optional for per-cell walkers, or split `apply_cache_effect` into per-cell and session-wide branches before the D3/D6 indexing work expands call volume.

4. LOW-4: `collect_cache_effects` allocates a fresh `Arc<str>` for every `RegisterFormat` walker pass.

   Scope: performance lifecycle.

   Evidence:

   - `collect_cache_effects` uses `Arc::<str>::from(string.as_str())` at `crates/ql-collab/src/session.rs:1099`.

   Impact:

   Full `rebuild_snapshot_cache` allocates once per `RegisterFormat` op per rebuild. This is not a current correctness issue, but it is unnecessary churn if format registration volume grows.

   Suggested closure:

   Share the stored string representation with the authoritative replay path where possible, or defer the allocation until the effect is actually applied to a session-owned cache.

## INFO findings

   Evidence:

### Probe 1: undo clears `RegisterFormat` cache and Workbook state

Command:

```bash
/Users/sanzhar/.cargo/bin/cargo test -p ql-collab --release --features test-fixtures --test codex_v3603_probe -- --nocapture
```

Relevant snippet:

```rust
#[test]
fn codex_probe_register_format_undo_clears_cache_and_workbook() {
    let registry = default_registry();
    let mut session = CollabSession::new(PeerId(1), &registry).unwrap();
    let id = FormatId::Custom { peer: PeerId(7), counter: 1 };

    session.append_op(register_custom(PeerId(7), 1, "0.00%")).unwrap();
    assert_eq!(cache_string(&session, id).as_deref(), Some("0.00%"));
    assert_eq!(session.rebuild_workbook().unwrap().formats().lookup(id).map(str::to_owned), Some("0.00%".to_string()));

    session.undo(&registry).unwrap();
    assert_eq!(session.op_count(), 0);
    assert_eq!(cache_string(&session, id), None);
    assert_eq!(session.rebuild_workbook().unwrap().formats().lookup(id), None);
}
```

Result: passed. This refutes the stale-cache undo concern.

### Probe 3: same-id/different-string conflict converges in cache but Workbook rejects

Command:


Relevant snippet:

```rust
#[test]
fn codex_probe_same_id_different_string_cache_converges_but_workbook_rejects() {
    let registry = default_registry();
    let id = FormatId::Custom { peer: PeerId(42), counter: 1 };

    let mut a = CollabSession::new(PeerId(1), &registry).unwrap();
    let mut b = CollabSession::new(PeerId(2), &registry).unwrap();
    let mut c = CollabSession::new(PeerId(3), &registry).unwrap();

    a.append_op(register_custom(PeerId(42), 1, "A_FMT")).unwrap();
    b.append_op(register_custom(PeerId(42), 1, "B_FMT")).unwrap();

    let a_bytes = a.export_snapshot_bytes().unwrap();
    let b_bytes = b.export_snapshot_bytes().unwrap();
    a.merge_bytes(&b_bytes, &registry).unwrap();
    b.merge_bytes(&a_bytes, &registry).unwrap();
    c.merge_bytes(&a.export_snapshot_bytes().unwrap(), &registry).unwrap();

    assert_eq!(cache_string(&a, id), cache_string(&b, id));
    assert_eq!(cache_string(&b, id), cache_string(&c, id));
    assert!(a.rebuild_workbook().is_err());
    assert!(b.rebuild_workbook().is_err());
    assert!(c.rebuild_workbook().is_err());
}
```

Observed output included:

```text
cache strings after merge: A=B_FMT, B=B_FMT, C=B_FMT
```

Result: passed, demonstrating MEDIUM-3.
