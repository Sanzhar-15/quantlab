## Specific review asks

1. **Excel canon correctness** — pick 3-5 functions you suspect might diverge from Excel canon and verify them against the IronCalc references at `.references/ironcalc/base/src/functions/` AND against Microsoft's official documentation. Specifically scrutinize:
   - SWITCH type-strictness + error propagation (already corrected per Codex HIGH-1 in W5-162.1, but verify the test suite covers it).
   - RATE / IRR Newton-Raphson behavior: tolerance + iteration cap match IronCalc.
   - PMT / FV / PV / NPER / IPMT / PPMT TVM equation matches IronCalc exactly.
   - NPV / IRR non-numeric handling: NPV skips, IRR rejects with #VALUE!.
   - XLOOKUP next-smaller / next-larger semantics on UNSORTED data: my impl tracks best candidate during linear scan — is that what Excel does, or does Excel assume sorted input?
   - ADDRESS sheet quoting rules: I quote if anything outside `[A-Za-z0-9_]`; Excel's actual rule is more nuanced (only quotes if starts with digit, contains certain chars, etc.).

2. **Cross-cutting consistency** — do all 44 new functions handle these the same way?
   - Empty arg list (some return #VALUE!, some might return #DIV/0!).
   - Errors in args (all should propagate; check for any that silently swallow).
   - Blank arg (coerced to 0 for math, "" for text — consistent?).
   - Wrong arity (all #VALUE!).

3. **Numerical stability** — RATE / IRR use Newton-Raphson. Specific concerns:
   - Does RATE handle near-zero rate gracefully? IronCalc has `rate == 0` short-circuit; I do too — verify.
   - Does IRR's bisection fallback correctly handle cash flows where N-R diverges?
   - Are the eps values (1e-7 for RATE, 1e-8 / 1e-10 for IRR) reasonable vs Excel's ~1e-9?

4. **Matrix accuracy** — `docs/compat/excel-matrix.md` was updated batch-by-batch. Any rows still tagged ❌ that should now be ✅? Any test-count fields outdated? Any rows where the Notes column is misleading?

5. **Test coverage gaps** — for each batch, what scenarios are NOT covered that should be? Examples to consider:

   - DOLLAR with negative decimals.
   - XLOOKUP if_not_found = a Range arg (my code returns #VALUE! — is that right?).
   - ADDRESS with sheet name containing single quotes (does my doubling rule work?).
   - Combinatoric overflow boundaries beyond what tests check.
