## LOW

### LOW-001

- **Subject:** Matrix test counts overstate the scalar test coverage
- **Where:** `docs/compat/excel-matrix.md:316`, `docs/compat/excel-matrix.md:317`, `docs/compat/excel-matrix.md:318`, `crates/ql-functions/src/scalar_fns.rs:7479`, `crates/ql-functions/src/scalar_fns.rs:7531`, `crates/ql-functions/src/scalar_fns.rs:7595`
- **Detail:** The matrix reports DEC2OCT as 9 tests, DEC2HEX as 10 tests, and BIN2DEC as 8 tests. The actual W5-D-9 scalar unit-test blocks contain 8 DEC2OCT tests, 9 DEC2HEX tests, and 7 BIN2DEC tests, for 50 scalar tests total rather than the stated 53. The implementation behavior is covered for the main anchors, but BIN2DEC also lacks a direct valid-binary out-of-range case such as `11111111111 -> #NUM!`.
- **Recommendation:** Either correct the matrix counts to the actual totals, or add three focused tests so the documented 53-test claim becomes true. Good candidates are `BIN2DEC(11111111111) -> #NUM!`, a DEC2OCT places-boundary test, and a DEC2HEX negative-with-places or places-boundary test.
- **Severity rationale:** Low because this is a coverage/accounting mismatch, not an observed runtime bug. The shipped implementation rejects the BIN2DEC out-of-range case through the parsed-value bound check.

### LOW-002

- **Subject:** Cross-cutting lexer branch is only indirectly pinned
- **Where:** `crates/ql-formula-syntax/src/lexer.rs:651`, `crates/ql-exec/tests/region_mul2_e2e.rs:553`
- **Detail:** The new `letters + digits + letters` lexer branch is exercised through the e2e dispatcher test (`DEC2BIN(5)`, `BIN2DEC(101)`, etc.), and the existing lexer suite still pins `LOG10(2)` as a trailing-digit-only CellRef path. However, there is no lexer-level unit test that directly asserts `DEC2BIN`/`BIN2DEC` tokenizes as `Token::Ident`, nor one that pins the absolute-marker guards (`$DEC2BIN`, `DEC$2BIN`) around this new branch.
- **Recommendation:** Add lexer tests near the existing `LOG10` ambiguity tests: `DEC2BIN(5)` should start with `Token::Ident("DEC2BIN")`, `BIN2DEC(101)` should start with `Token::Ident("BIN2DEC")`, `LOG10(2)` should remain the existing `CellRef + LParen` shape, and the guarded dollar cases should retain the intended malformed/trailing-token behavior.
- **Severity rationale:** Low because the e2e dispatcher test proves the user-facing base-conversion calls parse and dispatch, and `cargo test -p ql-formula-syntax lexer::tests` passed. Direct lexer tests would reduce regression risk for the cross-cutting tokenization change.
