## What to look for

### Correctness

1. **statrs API verification:** `StudentsT::new(location, scale, freedom)` with `(0.0, 1.0, df)`; `cdf(x)`, `pdf(x)`, `inverse_cdf(p)`. Verify all 5 impls use these correctly. `students_t_with(df)` helper uses `.expect()` per No-Fallbacks rule.
2. **Domain checks match Excel/IronCalc canon:**
   - T.DIST: `df` truncated to integer (`.trunc()`); `df >= 1.0` else `#NUM!`.
   - T.DIST.2T: `x >= 0.0` AND `df >= 1.0` else `#NUM!`. (Note: x rejection is canon, not arbitrary.)
   - T.DIST.RT: `df >= 1.0` only; negative `x` is ALLOWED (unlike T.DIST.2T).
   - T.INV: `0.0 < p < 1.0` STRICT (both endpoints excluded) AND `df >= 1.0` else `#NUM!`.
   - T.INV.2T: `0.0 < p <= 1.0` — note **upper-inclusive** (p=1 → 0). df >= 1. Else #NUM!.
3. **T.DIST.2T clamping:** result `2*(1-cdf(x))` clamped to `[0,1]` — verify the clamp is correctly defensive (per IronCalc).
4. **T.DIST.RT negative-result guard:** `1 - cdf(x)` checked for `< 0` → `#NUM!`. Verify.
5. **T.INV.2T inversion math:** `inverse_cdf(1 - p/2).abs()` — verify this matches IronCalc and the closed-form for `P(|T| >= x) = p ⇒ x = CDF⁻¹(1 - p/2)`.
6. **`finite_or_num` routing:** all 5 fns must route non-finite statrs outputs through `#NUM!`. Verify by reading each impl.
7. **Coercion:** numeric args via `to_number_strict`; cumulative flag (T.DIST only) via `to_logical`. Same divergences as W5-D-1 (Booleans → 0/1 vs IronCalc rejects).
8. **Arity:** strict — wrong count → `#VALUE!` (codebase convention, NOT `#N/A` — verify all 5 use Value).
9. **Anchor values vs LibreOffice 7.6:**
   - T.DIST(0, df, TRUE) = 0.5 (any df, symmetry).
   - T.DIST(0, 1, FALSE) = 1/π ≈ 0.31830988618379067.
   - T.DIST(1, 1, TRUE) = 0.75 (closed-form: ½ + arctan(1)/π = ½ + ¼).
   - T.DIST(1, 1, FALSE) = 1/(2π) ≈ 0.15915494309189535.
   - T.DIST.2T(1, 1) = 0.5.
   - T.DIST.RT(0, df) = 0.5; T.DIST.RT(1, 1) = 0.25; T.DIST.RT(-1, 1) = 0.75.
   - T.INV(0.975, 10) ≈ 2.228138851938055 (standard t-critical).
   - T.INV.2T(0.05, 30) ≈ 2.042272456301236 (standard 5% two-tailed crit).
   - Verify these are correct.

### Lexer change (CROSS-CUTTING — read carefully)

10. **Lexer `lex_identifier_or_cellref`:** new branch for `.DIGIT+LETTER...` segments. Verify:
    - Letter-leading segment retains pre-W5-D-2 strict letters/underscore rule.
    - Digit-leading segment requires ≥1 letter (rejects pure-digit `.123`).
    - The `has_dot` post-loop reject-trailing-digit guard still catches `VAR.S5`-style typos (since letter-segments don't absorb digits).
    - Multi-segment patterns work: `T.DIST.2T`, `T.INV.2T`, `F.DIST.RT`, `CHISQ.DIST.RT`.
    - Edge case: `T.DIST.` (orphan dot at end) → reject.
    - Edge case: `T.DIST.2` (digit segment with no letter) → reject.
    - Edge case: `T.DIST.2T1` (alphanumeric continuation after letter in digit segment) — currently accepted (becomes unknown function name). Acceptable per binder rejection of unknown names.
    - No new lexer tests added for the digit-segment path — this is a test gap. Flag.
