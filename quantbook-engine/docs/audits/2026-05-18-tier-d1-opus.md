# Opus audit — Tier D1 WorkbookRuntime split

## Verdict

**Zero HIGH, MEDIUM, or LOW findings.** The split is correctly
executed across all 8 audited dimensions.

## OK items (verified)

- **Sibling impl-block pattern**: All 9 submodules correctly
  declare `impl<'a> WorkbookRuntime<'a>` blocks extending the
  same struct. No orphan-impl-rule violations. Module visibility
  correctly grants access to private fields across siblings.
- **Private-field access**: Idiomatic Rust. Sibling modules
  access `self.workbook`, `self.registry`, `self.oplog`,
  `self.plan_cache`, `self.format_cache`, `self.graph` directly
  via sibling-module visibility within `crate::workbook_runtime`.
- **Method visibility transitions**: `write_spill` is correctly
  elevated to `pub(super)` (cells.rs:624) for call from
  recompute.rs:802. All other private methods
  (`try_recompute_one_cached`,
  `try_recompute_with_aggregate_cache`,
  `try_recompute_with_simd_profile`, `write_anchor_error`,
  `reextract_spill_footprint_readers`, `reextract_table_readers`)
  remain private (`fn`) as intended — called only within their
  own submodules.
- **Test fixture drift**: All 6 copies of
  `make_runtime_workbook()` are byte-identical across
  config.rs:82, cells.rs:1128, validate.rs:149, names.rs:163,
  recompute.rs:824, tables.rs:870. All properly scoped within
  `#[cfg(test)] mod tests`.
- **Doc-comment integrity**: Step 3.3's fix (mentioned in
  mod.rs:126–130) correctly addressed the `validate_cell` doc
  that was previously misattached to
  `rewrite_formula_text_for_sheet_rename`; the helper now lives
  as a free function in sheets.rs:37 (module-private). Opus did
  NOT catch the `recompute_all` doc misattachment to
  `validate_formula` — Codex did. See consolidated doc.
- **Test count rigor**: `MAX_ROW` constant imported correctly
  in cells.rs:33 and used identically in cells.rs tests
  (line 1124, line 2283). No constant drift detected.
- **`pub use` re-export integrity**: mod.rs:101 exports
  `{RecomputeFailure, RecomputeResult, RuntimeError}` correctly.
  All three types present in error.rs (lines 30, 201, 255).
  External callers (loader.rs, transaction.rs,
  calcgraph_session.rs, lib.rs:152) import unchanged.
- **Phase 2B.7 cluster placement**: `add_sheet` tests in
  validate.rs::tests are semantically validation-related;
  acceptable per the design doc. Codex disagreed (L-2/L-3); see
  consolidated doc for the disposition.
- **No code smells**: Zero TODO/FIXME/XXX/HACK comments. Import
  counts are proportionate per submodule. All commits compile
  cleanly.

## Where Opus missed what Codex caught

Codex surfaced 2 MEDIUMs and 5 LOWs that this audit missed:
- **M-1 (Codex)**: `recompute_all` doc misattached to
  `validate_formula` in validate.rs (got pulled with the Step
  3.8 move from a hanging doc block in mod.rs). Closed in the
  audit-closure commit.
- **M-2 (Codex)**: mod.rs at 299 LOC was above the ≤ 250
  acceptance target due to extraction-history block + stale tail
  comments. Closed by trimming to ~70 LOC of essential content;
  final mod.rs at 247 LOC.
- **L-1 (Codex)**: `validate_sheet` was `pub(crate)` but only
  called by `validate_cell`. Tightened to private.
- **L-2..L-5 (Codex)**: test partitioning polish items
  (add_sheet tests in validate.rs, clear_formula tests in
  validate.rs, W5-147 set_formula tests in tables.rs, drop_table
  tests in cells.rs, set_reference_mode test in tables.rs).
  Deferred to v2 backlog as low-priority polish — see
  consolidated doc.

This is a textbook example of why the 2-way audit (Codex + Opus)
catches more than either alone. Opus's "everything looks fine"
verdict missed the doc misattachment, which is exactly the
class of issue (hanging doc-block between two unrelated fns)
that Opus prefers to skim past while Codex follows up on with
grep-based verification.
