    81	    /// they poll the underlying channel; the contract is "if you
    82	    /// have something, give it to me, else `None`."

    84	    /// Returns `Err(TransportError::Closed)` only when the channel
    85	    /// is permanently closed AND its internal queue is empty. A
    86	    /// transient I/O failure during poll surfaces as
    87	    /// `Err(TransportError::Io)`.
    88	    fn try_recv(&mut self) -> Result<Option<Vec<u8>>, TransportError>;

   142	/// impl for 2-peer round-trip testing.
   143	///
   144	/// Constructed via [`LoopbackTransport::pair`]: returns two

   147	/// `Arc<Mutex<VecDeque<Vec<u8>>>>` channels via interior
   148	/// mutability — `Send + Sync` so they can also be used across

   150	///
   151	/// ## Use case
   152	///
   153	/// Wire two `CollabSession`s together for tests like:
   154	/// ```ignore
   155	/// let (mut tx_a, mut tx_b) = LoopbackTransport::pair();
   156	/// let session_a = CollabSession::new(PeerId::new(1))?;

   161	/// CollabSession does NOT auto-flush to its attached Transport
   162	/// in V1 (Phase 5.5 V2 will wire append → send). For now, tests
   163	/// drive the flow manually: append, export_bytes, send via the
   164	/// transport, recv on the other side, merge_bytes.
   165	///
   166	/// ## Close semantics
   167	///
   168	/// Each endpoint has its OWN `closed` flag (separate
   169	/// `AtomicBool`). `a.close()` shuts down endpoint A:
   170	/// - A's `send` returns `TransportError::Closed` immediately.
   171	/// - A's `try_recv` drains any already-queued bytes FIRST and
   172	///   only returns `Closed` once the queue is empty (per the
   173	///   `Transport` trait contract at the trait docstring).
   174	/// - B is unaffected: B can still `send` (bytes land in A's
   175	///   inbox; A drains them on the next try_recv before reporting
   176	///   Closed) and `try_recv` (drains B's inbox).
   177	///
   178	/// ## Atomic ordering caveat
   179	///
   180	/// `close` uses `AtomicBool` with `Relaxed` ordering. For
   181	/// cross-thread "close then send" semantics, callers must use
   182	/// external synchronization — a thread that observes
   183	/// `is_closed() == true` after another thread's `close()` is NOT
   184	/// guaranteed by this transport alone (the atomic only protects
   185	/// the flag itself, not the surrounding sequence).
   186	pub struct LoopbackTransport {
   187	    /// Channel WE drain via `try_recv`. The peer's `send` writes
   188	    /// here.
   189	    inbox: Arc<Mutex<VecDeque<Vec<u8>>>>,
   190	    /// Channel WE write to via `send`. The peer's `try_recv`
   191	    /// drains here.
   192	    outbox: Arc<Mutex<VecDeque<Vec<u8>>>>,
   193	    /// Per-endpoint close flag. Atomic so `close(&self)` doesn't
   194	    /// need `&mut`.
   195	    closed: AtomicBool,
   196	}

    12	# Phase 5.5 V2 V2 — auto-flush on append
    13	
    14	## Why
    15	
    16	Pre-V2 V2: `CollabSession::flush_to_transport()` is explicit-drive. Callers must invoke flush after every append (or batch + invoke once). This is awkward for IDE binding (Phase 5.7) — the IDE just wants "every keystroke propagates" without scheduling its own flush ticks.
    17	
    18	V2 V2 closes that gap by adding an opt-in auto-flush policy. The policy lives on the session; once set, every method that mutates the underlying `LoroDoc` also flushes to the attached transport (if one is attached).
    19	
    20	Per Phase 5.5 audit-locked decision V2 V1: V2 V1 was deliberately explicit-drive so the auto-flush design could land cleanly in V2 V2 without breaking V2 V1 callers. V2 V2 preserves V2 V1 behavior by default (`AutoFlushPolicy::Disabled`).
    21	
    22	## Design
    23	
    24	### API addition
    25	
    26	```rust
    27	/// Auto-flush policy for [`CollabSession`].
    28	///
    29	/// Determines when (if ever) the session pushes its current snapshot
    30	/// through the attached transport without an explicit
    31	/// [`CollabSession::flush_to_transport`] call.
    32	///
    33	/// V2 V2 (this ship) adds two variants. V2 V3 will add a `Threshold`
    34	/// variant for byte-budget-based batching.
    35	#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
    36	#[non_exhaustive]
    37	pub enum AutoFlushPolicy {
    38	    /// Default. V2 V1 behavior preserved: caller drives flush + poll
    39	    /// explicitly. Auto-flush never fires.
    40	    #[default]
    41	    Disabled,
    42	    /// Flush automatically after every method that mutates the
    43	    /// underlying `LoroDoc`. Includes: `append_op`, `merge_bytes`,
    44	    /// `update_presence`, `clear_presence`, `sweep_presence`,
    45	    /// `undo`, `redo`. Does NOT include accessor methods that don't
    46	    /// mutate (`peer_presence`, `op_log`, etc.).
    47	    OnAppend,
    48	}
    49	```
    50	
    51	```rust
    52	impl CollabSession {
    53	    /// Set the auto-flush policy. Returns the previous policy.
    54	    pub fn set_auto_flush_policy(&mut self, policy: AutoFlushPolicy) -> AutoFlushPolicy;
    55	
    56	    /// Read the current auto-flush policy.
    57	    pub fn auto_flush_policy(&self) -> AutoFlushPolicy;
    58	}
    59	```
    60	
    61	### Behavior contract
    62	
    63	- **Default**: `AutoFlushPolicy::Disabled` (preserves V2 V1 behavior; no breaking change).
    64	- **OnAppend**: after each public mutator on `CollabSession` succeeds at the LoroDoc layer, the session calls `flush_to_transport()` internally. No-op if no transport attached. If `flush_to_transport()` returns `Err`, that error propagates from the calling method.
    65	- **Partial-state contract on auto-flush error**: per CLAUDE.md No-Fallback rule, transport errors MUST be visible. When auto-flush fails, the local mutation has ALREADY been committed to `self.log` (mutate-then-flush ordering). The caller's `Err` says "the op is in your local log but did NOT reach the transport". The session's op log is consistent; the wire is what's lagging.
    66	
    67	  Callers handling this should:
    68	  1. Treat the local state as authoritative for the local UI.
    69	  2. Mark the session as "out of sync" and either retry the flush (transport recovered) or drop the transport.
    70	  3. NOT roll back the local op (Loro doesn't support "ungrowing" an op log; the V1 limitation tracker H7 already covers this).
    71	
    72	### Methods that trigger auto-flush
    73	
    74	After this V2 V2 ship, the following methods invoke auto-flush internally when policy is `OnAppend` and a transport is attached:
    75	
    76	| Method | Reason |
    77	|---|---|
    78	| `append_op` | Primary write path — every local op needs to reach peers |
    79	| `merge_bytes` | After merging peer ops, our snapshot now contains peer state; subsequent peers should see the union via our flush |
    80	| `update_presence` | Cursor/selection presence is meaningless if it doesn't propagate |
    81	| `clear_presence` | "I left the session" must reach peers |
    82	| `sweep_presence` | Same |
    83	| `undo`, `redo` | Loro appends inverse ops to the log; peers see them |
    84	
    85	Methods explicitly NOT triggering auto-flush:
    86	- `start_undo_group`, `end_undo_group` — group boundaries only affect local undo stack semantics; the ops INSIDE the group already trigger via `append_op`. Auto-flush on group boundaries would be redundant.
    87	- `attach_transport`, `detach_transport` — transport lifecycle, not a session mutation
    88	- `set_auto_flush_policy` — policy change, doesn't add ops
    89	- All read-only methods
    90	
    91	### Implementation strategy
    92	
    93	A single private helper method `maybe_auto_flush(&mut self) -> Result<(), CollabSessionError>`:
    94	
    95	```rust
    96	/// Internal hook called after every public mutator on `self.log`.
    97	/// If `auto_flush_policy == OnAppend` AND a transport is attached,
    98	/// invokes `flush_to_transport`. Otherwise no-op.
    99	///
   100	/// Errors from `flush_to_transport` propagate to the caller.
   101	fn maybe_auto_flush(&mut self) -> Result<(), CollabSessionError> {
   102	    if matches!(self.auto_flush_policy, AutoFlushPolicy::Disabled) {
   103	        return Ok(());
   104	    }
   105	    if self.transport.is_none() {
   106	        return Ok(());
   107	    }
   108	    let _sent = self.flush_to_transport()?;
   109	    Ok(())
   110	}
   111	```
   112	
   113	Each public mutator gets a single line added before its `Ok(...)`:
   114	
   115	```rust
   116	pub fn append_op(&mut self, op: Op) -> Result<(), CollabSessionError> {
   117	    self.log.append(op)?;
   118	    self.maybe_auto_flush()?;     // ← new
   119	    Ok(())
   120	}
   121	```
