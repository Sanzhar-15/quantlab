# Codex audit — VDB (W5-183, closes Wave 3 depreciation batch)

## Scope

Single commit `f81965a0a9c` (W5-183) on `feat/quantbook-engine`:
adds `VDB(cost, salvage, life, start_period, end_period, [factor=2],
[no_switch=FALSE])` to the financial functions module. **Closes the
Wave 3 depreciation batch** — VDB is the 5th and final function.

**Audit risk:** higher than the SLN/SYD/DDB/DB audit because:

1. **No IronCalc Rust reference** — IronCalc has VDB in their docs
   nav but NOT in `base/src/functions/`. The algorithm was derived
   directly from Microsoft's 6 documented examples + the canonical
   period-iteration form.
2. **Complex state** — period-iteration with switching state, locked-
   in SLN per-period amount, fractional start/end overlap math.
3. **Microsoft docs are sparse** on edge cases — they list 6 examples
   but no Remarks section with error codes or boundary semantics.

## What to find

For VDB specifically, look for:

1. **Algorithm correctness vs Microsoft examples.** Re-verify each of
   the 6 fixtures by hand (or by Python/spreadsheet sanity check):
   - VDB(2400, 300, 10×365, 0, 1) = $1.32
   - VDB(2400, 300, 10×12, 0, 1) = $40.00
   - VDB(2400, 300, 10, 0, 1) = $480.00
   - VDB(2400, 300, 10×12, 6, 18) = $396.31
   - VDB(2400, 300, 10×12, 6, 18, 1.5) = $311.81
   - VDB(2400, 300, 10, 0, 0.875, 1.5) = $315.00

   Our impl passes all 6 within the documented tolerances. Verify
   the algorithm matches Microsoft's intent, not just the displayed
   values.

2. **Crossover semantics.** Once `sln_now > ddb_now`, we lock in
   `sln_per_period` and use that constant value for all remaining
   periods. Is this the correct Excel behavior? Some implementations
   recompute SLN each period from the current book. Verify by:
   - Checking VDB output for periods spanning the crossover (e.g.,
     VDB(1000, 100, 10, 5, 7)).
   - Comparing against the locked-in vs recomputed interpretation.

3. **Fractional start/end overlap math.** The line `total += period_dep
   * overlap` where `overlap = (min(i+1, end) − max(i, start)).max(0.0)`.
   Verify for:
   - start=0.5, end=1.5 (partial first + partial second period).
   - start=0, end=0.875 (partial period 1 only — pinned at 315.00).
   - start=2.3, end=4.7 (covers part of period 3, all of period 4,
     part of period 5).

4. **Book depletion vs overlap accounting.** Book updates by FULL
   `period_dep`, not `overlap * period_dep`. Is this correct? The
   intent is: depreciation accrues whether or not the period is in
   the requested range. Verify this matches Excel — e.g., VDB(_, _,
   _, 5, 7) should not equal sum of "fresh book" period-by-period
   computations.

5. **Period 0 vs period 1 indexing.** Microsoft uses `start_period=0`
   for "from the beginning" (no period before this) and `end_period=1`
   for "through end of period 1". Our loop iterates `0..end_ceil`,
   so period index 0 is the first period (months 0..1). Verify the
   overlap with `start_period=0` is `[0, 1]` (full first period).

6. **`no_switch` semantics.** When TRUE, never switches to SLN — but
   still applies the salvage cap via `min(book·rate, book−salvage)`.
   Is that correct? Some interpretations of "no_switch" mean
   "uncapped DDB" too. Verify against Microsoft (their docs are
   silent on this).

7. **Validation gaps** (same checklist as W5-180/181/182):
   - All 5 validation `#NUM!` paths pinned independently.
   - `cost == 0` short-circuit.
   - `start == end` short-circuit (correct: no periods to sum, return 0).
   - i32 overflow guard (same pattern as W5-182.1 DB).
   - Arity boundaries (5 / 6 / 7 args; 4 or 8 should reject).
   - Error propagation in any arg position.

8. **`no_switch` Boolean coercion.** Uses `arg_type` (Boolean-strict)
   while other args use `arg_num`. Verify error propagation through
   `arg_type` works for Error inputs to that slot.

9. **Off-by-one or sign mistakes** in:
   - `periods_remaining = (life - period_f).max(1.0)` — should this
     be `life - period_f` (count INCLUDING current) or `life - period_f - 1`
     (count EXCLUDING current)? Both interpretations exist; which is
     correct for VDB's SLN-check?
   - The locked-in `sln_per_period` value — is it the SLN at the
     moment of switch, or recomputed each subsequent period? Our impl
     locks it in.
   - `end_ceil` cast — what happens for non-integer end_period?

10. **Documentation accuracy.**
    - Doc-comment algorithm pseudo-code vs impl behavior.
    - Matrix description vs impl behavior.
    - Coverage entry vs what tests actually pin.
