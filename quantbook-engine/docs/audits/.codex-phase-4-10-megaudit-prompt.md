## Megaudit angles — find issues across these dimensions

### 1. Registry-matrix-coverage three-way drift

Run `cargo test -p ql-functions default_registry_has_expected_count`
and `cargo test -p ql-functions coverage`. Verify all 260 fns exist
in the registry, have a matrix entry in `docs/compat/excel-matrix.md`,
and have an `EXPLICITLY_DEFERRED` coverage entry in
`crates/ql-functions/tests/coverage.rs`. Any of:
- Registered but no matrix entry.
- Registered but no coverage entry.
- Matrix entry but not registered (✅ status with no impl).
- Coverage entry but not registered.

would be a real drift. Use the matrix coverage script
`bash scripts/report-compat-coverage.sh` as one signal.

### 2. is_aggregate_function admission completeness

`plan.rs::is_aggregate_function` is the binder's admission gate for
range-aware fns that take range args. W5-D-12 added SUBTOTAL. Per
the invariant test `is_aggregate_function_lists_only_registered_
aggregates` at `workbook_runtime.rs:5158`, every entry must be
registered AND every registered range-aware fn that takes a range
arg MUST be admitted.

**Audit every range-aware fn shipped in Phase 4.10** and verify
admission. The 22 closeout fns include several range-aware:
- COVARIANCE.P / COVARIANCE.S (W5-D-6).
- XNPV / XIRR (W5-D-7).
- PERCENTILE.* / QUARTILE.* / PERCENTILE / QUARTILE (W5-D-11).
- SUBTOTAL (W5-D-12).

Are all of these in `is_aggregate_function`? If not, that's a real
binder gap (matching the W5-D-12 Codex HIGH-001 pattern that the
SUBTOTAL audit caught).

### 3. NaN-leak / saturating f64→integer patterns

W5-D-11 caught `extract_quartile_q` saturating NaN→0 leak. W5-D-12
added the same guard to SUBTOTAL function_num extraction.

**Find every f64→integer cast across Phase 4.10 fns** (use `grep -rn
"as i64\|as u64\|as usize\|as i32\|as u32" crates/ql-functions/src/`
limiting to W5-D-* sections) and verify each one either has an
explicit `is_nan()` guard OR the bound check catches NaN cleanly via
the `(range).contains(&n) == false` short-circuit pattern.

Particularly look at:
- `extract_percentile_k` (W5-D-11) — accepts NaN; relies on
  downstream bound-check. Verify the contains-check actually catches
  NaN.
- `parse_places_arg` (W5-D-9 base conversion) — converts the
  optional `places` arg.
- Any iterative-kernel max-iterations.

### 4. Literal-RangeRef in AggregateArg deferral consistency

`plan.rs:706-731` says literal `Expr::RangeRef` is rejected outside
`BindContext::ReferenceArg`. This affects EVERY aggregate in Phase
4.10, not just SUBTOTAL.

Verify the matrix entries for COVARIANCE.P, COVARIANCE.S, XNPV,
XIRR, PERCENTILE.INC, PERCENTILE.EXC, QUARTILE.INC, QUARTILE.EXC
all acknowledge this v1 gap somehow. If only SUBTOTAL's matrix entry
mentions it (as the only one with the 🟡 marker), that's an honesty
gap.

### 6. Cross-cutting lexer extension test coverage

### 7. Statrs iterative-kernel corner-case audit

boundaries can panic OR hang.

**Re-audit every distribution fn in Wave 3 for the OTHER corner
that wasn't caught.** E.g.:
- BINOM.DIST / BINOM.DIST.RANGE — `p=0`, `p=1`, `n=0`?
- NEGBINOM.DIST — `r=0`, `p=0`, `p=1`?
- POISSON.DIST — `lambda=0`, very-large lambda?
- LOGNORM.DIST / LOGNORM.INV — sigma=0?
- GAMMA.DIST — alpha=0, beta=0?
- BETA.DIST — alpha=0, beta=0?
- F.DIST / F.INV — df1=0, df2=0?
- T.DIST / T.INV — df=0, very-small df?
- CHISQ.DIST / CHISQ.INV — df=0?

For each, compile-probe (in a `/tmp/probe-*` crate) the corner and
see if the engine panics, hangs, or returns a defensible error.
