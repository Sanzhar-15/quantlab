## Concerns by area

### A. Parser (W5-77b)

**A.1** Token disambiguation rules per mini-spec § 4.1 (m/mm month-vs-minute) — does the look-ahead/look-behind cover all cases? Specifically check `h:mm:ss`, `mm:ss`, `mmm m`, `h:m`, lone `mm` in date-only context.

**A.2** Comma resolution (§ 5): thousands separator vs scale-by-thousands. Pending-comma counter logic. Cases: `#,##0`, `#,`, `#,,`, `#,##0,`, edge case `,0` (literal comma before any digit).

**A.3** Bracket-block dispatch (`[$€-409]` currency vs `[Red]` color vs `[>100]` conditional vs `[h]` elapsed). LCID hex parsing — does invalid hex surface a clean error rather than panicking?

**A.4** Length-limit validation: `yyy`, `mmmmmm`, `ddddd` should each error with specific Other messages; `hhhh`/`ssss` likewise.

**A.5** Error position fidelity — does `UnterminatedQuotedText`, `TrailingBackslash`, `TrailingSpacerOrGhost` all point to the offending character's index?

### B. Renderer (W5-78)

**B.1** Section routing for negative values per mini-spec § 3: 1-section auto-prepends `-`; 2/3/4-section formats DON'T auto-prepend because the negative section owns sign rendering. Verify with `0`, `0;-0`, `0;(0)`, `0;-0;0;@`.

**B.2** Time-only sections: serial 0.5 with `h:mm:ss` (no Year/Month/Day token) must NOT fail through `serial_to_ymd` even in Excel1900 where serial 0 is rejected. (W5-78 fix.)

**B.3** AM/PM hour conversion: 0 → 12 AM, 1-11 → 1-11 AM, 12 → 12 PM, 13-23 → 1-11 PM.

**B.4** Built-in format-id round-trip per mini-spec § 10 (ids 0/1/2/3/4/9/10/11/14-22/37/45/49). Each should parse cleanly and render the expected output for representative values.

**B.5** Excel-quirk divergences: `YEARFRAC(_, 4)` returned 1.0 for Jan 1→Dec 31 (intentional non-adjustment); does `format::render` produce results consistent with Excel's idiosyncratic but expected behavior?

**B.6** Cache behavior + EvalContext threading from runtime's read_display: the format_cache stores `FormatString` per `FormatId`; the EvalContext uses workbook's date_system. Verify both threading through W5-82 + W5-83 tests don't break for non-default contexts.

### C. Storage layer (W5-79)

**C.1** FormatTable.intern allocator: monotonic in insertion order; built-ins pre-seeded; register_at idempotent on same-string-same-id; rejects different-string-at-id and same-string-at-different-id.

**C.2** CellFormatOverlay: get/set/clear/clear_all/iter/count_refs all sane. Independent sheets stay isolated. The flat HashMap shape (vs design-doc chunk-based shape) is documented as a V1 simplification.

**C.3** Workbook + Sheet integration: `formats()` / `formats_mut()`, `format_overlay()` / `format_overlay_mut()` are reachable from both loader (low-level) and runtime (op-log-recording) paths.

### D. Op-log (W5-80)

**D.1** Op::RegisterFormat replay idempotency: re-registering id 0 = "General" must succeed; id 0 = "WRONG" must fail with FormatRejected{IdCollision}; id 200 = "General" (where "General" is already at id 0) must fail with FormatRejected{StringCollision}.

**D.2** Op::SetCellFormat with unknown id surfaces as FormatNotRegistered (not silently bound). The producer-side check in WorkbookRuntime::set_cell_format mirrors this.

**D.3** Producer-replay equivalence (`tests/producer_replay_equivalence.rs`): the new variants survive through the realistic-op-sequence test pattern.

**D.4** BatchCommit nesting: a BatchCommit { ops: [RegisterFormat, SetCellFormat] } replays the inner ops in order. Verify by inspection.

### E. .qbook schema v3 → v4 (W5-81)

**E.1** Backwards-compat: a v3 envelope (no `formats`, no `format_overlay`) loads on v4 reader as empty FormatTable defaults + empty overlays. Regression-neutral confirmed by `v3_envelope_missing_formats_loads_with_defaults`.

**E.2** Forward-compat: v3 reader REFUSES v4 via existing UnsupportedSchema path; v4 reader REFUSES v5. (Tested.)

**E.3** Save-side: built-ins are NOT persisted (no `[formats]` table in TOML when no custom entries). Verified by `empty_format_table_round_trips_without_persisting_builtins`.

**E.4** Save-side determinism: FormatsSection entries sorted by id; format_overlay entries sorted by (row, col).

**E.5** Load-side validation: MalformedFormat surfaces collisions cleanly; MalformedFormatOverlay surfaces out-of-range coords cleanly.

**E.6** Atomicity: schema bump uses existing atomic-save protocol (engine-owned-marker recovery). No regressions.

### F. Runtime wrappers + read_display (W5-82)

**F.1** intern_format append-before-mutate ordering: a failing oplog.append leaves the FormatTable unchanged. Verify via the `RuntimeError::OpLog` path (e.g. NaN in PutValue).

**F.2** intern_format idempotency: built-ins return their id WITHOUT emitting a RegisterFormat op; new custom string emits exactly one op; repeated intern of same string emits no second op.

**F.3** set_cell_format unknown-id rejection: `Some(FormatId(9999))` returns `RuntimeError::UnknownFormatId(9999)` BEFORE any oplog mutation.

**F.4** read_display correctness: General fallback when overlay missing; date format renders via serial_to_ymd; custom format renders via FormatTable lookup; error sigil passes through unchanged.

**F.5** format_cache stability: parsed FormatStrings live for the runtime's lifetime; cache only inserts (never invalidates).

### G. TEXT() function (W5-83)

**G.1** Error propagation: TEXT(#NUM!, "0") → #NUM!; TEXT(1, #REF!) → #REF!. Both flow through.

**G.2** Format-arg coercion: Text accepted; Blank treated as empty; Number/Boolean → #VALUE!.

**G.3** Empty format string returns empty text (Excel canon).

**G.4** Parse failure (e.g. "[Red]0") → #VALUE!.

**G.5** Integration through set_formula → recompute: TEXT formula's evaluated value is `Value::Text("...")` containing the rendered string.

**G.6** EvalContext threading via ContextAwareFn dispatch: TEXT correctly reads workbook's date_system (1900 vs 1904).

### H. Cross-cutting / arch concerns

**H.1** Does the parser's V2-deferred surface stay aligned with what the renderer + TEXT() expect? E.g., if TEXT parses an "[Red]0" format, the parser returns UnsupportedV2; TEXT translates to #VALUE!. Are there any V2 tokens whose parser refusal is inconsistent with the renderer's panic-on-unknown behavior?

**H.2** Mini-spec § 10 built-in format-id table: the 18 pre-seeded entries cover the parser-relevant subset. Does that match what xlsx import in Phase 4.11 will need? Are any commonly-used built-ins missing that could surface as MalformedFormat at xlsx load time?

**H.3** Coverage gating: `coverage.rs` only has TEXT in EXPLICITLY_DEFERRED. Are the matrix tests (excel-matrix.md) updated to include TEXT() canonical examples, or is this a pending gap?

**H.4** GAP-F-07 (FormatTable compaction): when a cell's format is overridden, the old FormatId stays in the table. `count_refs` exists to support compaction but no compaction is wired yet. Is this risk documented in `known-gaps.md`? Should W5-84 update the GAP entry?

**H.5** Workbook::set_date_system docstring (updated W5-76) warns about WorkbookEnv staleness. Does the new format_cache on WorkbookRuntime have a similar staleness concern when the workbook's FormatTable is mutated through `formats_mut()` outside the runtime?
