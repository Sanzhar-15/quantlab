# Opus audit — Phase 5.5 V2 V1 (CollabSession transport wrappers)

Auditor: Opus subagent.
HEAD audited: `ffd8f6e5f05`.
Total: 64,951 tokens / 23 tool uses / 123s.

## HIGH

**H1 — `poll_remote` has no bound on the drain loop.** Adversarial
or chatty transport can fill the inbox faster than we drain;
one `poll_remote` call blocks the calling thread arbitrarily.
Fix: add a `max_blobs` parameter (or `poll_remote_with_limit`)
and document the bound.

**H2 — `flush_to_transport` docstring inaccurate.** Says "transport
errors" but `export_bytes()?` returns `OpLog` variant, not
`Transport`. Reword: errors propagate from `OpLog` (encode) or
`Transport` (send); local `OpLog` unaffected in both cases.

**H3 — Send/Sync contract on `CollabSession` not pinned in code.**
Docstring promises threadable sessions but no `_ASSERT_COLLAB_SESSION_SEND`.
Loro Send/Sync is non-obvious (historically `!Sync`); future dep
bump could break the promise silently. Add static assertion
mirroring `LoopbackTransport`'s pattern.

## MEDIUM

- M1: Doc drift across 4 files (transport.rs, crdt-data-model.md, entry-plan.md, known-gaps.md).
- M2: `detach_transport` returns `Box<dyn Transport + Send>` — caller can't downcast back to concrete impl. Document the loss-of-concrete-type.
- M3: `Result<bool>` tristate on `flush_to_transport` is awkward. Consider FlushOutcome enum.
- M4: Test gaps (close+flush, partial-drain+closed, attach-detach-reattach cycle, value-level convergence).
- M5: `attach_transport` replace-semantic silently loses peer's pending recv data. Document.

## LOW

- L1: docstring mixes "V2 V1 / V3" — should be "V2 V2 / V3".
- L2: `CollabSessionError::Transport` says "retry the flush/poll" — for `Closed`, retry is futile. Caveat.
- L3: poll_remote_drains test uses same snapshot twice — second merge is no-op. Use distinct snapshots.
- L4: V2 V2 will need a struct holding `(transport, version_vector, ...)` — current field shape will refactor. Worth a forward-implication comment.
- L5: Debug field `transport_attached` is bool, not Debug. Acceptable.

## Verdict

**Recommend 1-day fix pass before exit:**
- Must-fix before exit: H1 (bound), H2 (one-line doc), H3 (one-line Send pin).
- Must-fix soon (closure batch): M1 doc-drift quartet, M3 docstring on `Ok(false)`, M4 test gaps.

The code is sound: trait object-safe, Send bound correct,
replace/take/as_mut idiomatic, error mapping via `#[from]` clean,
drain-before-Closed honored. Concerns cluster on **doc accuracy
+ bound on poll_remote + Send pin**, not correctness.
