## Concerns by area

### A. Sheet registry + canonicalizer (W5-86)

**A.1** `Workbook::canonical_sheet_name`: ASCII-uppercase only? Confirm it matches the documented contract in the design doc § 10.0. Verify it agrees with `NameTable`'s canonicalization (also ASCII-uppercase).

**A.2** `Workbook::sheet_id_by_name`: case-insensitive lookup. Verify it handles non-ASCII (e.g. `Café` vs `CAFÉ`) consistently with the canonicalizer (i.e. they should NOT match, since canonicalization is ASCII-only — but this should be documented).

**A.3** `Workbook::validate_sheet_name`: rejects empty, reserved chars `: \ / ? * [ ]`, duplicates under canonical comparison. Verify the order: empty → reserved-char → duplicate. Does the reserved-char check fire for chars ANYWHERE in the name (not just first/last)?

**A.4** `Workbook::add_sheet` collision check: does it now use the canonical comparison? Pre-W5-86 the check was exact-name. Verify `add_sheet("Sheet1")` + `add_sheet("SHEET1")` rejects the second.

### B. SheetRef AST migration (W5-87)

**B.1** `SheetRef::resolve_or(owning_sheet)`: panics on `Name(_)` per design doc § 5.2. Verify the panic message is helpful + the panic is reachable ONLY from post-bind layers (binder/runtime), never from parser/printer.

**B.2** `SheetRef::from_option` + `SheetRef::id`: backwards-compat helpers. Verify their semantics match the historical `Option<SheetId>` shape.

**B.3** Hash/Eq for `SheetRef`: `Current` / `Name("X")` / `Id(0)` all distinct? Verify `Name("Sheet1")` != `Name("SHEET1")` (the AST does NOT canonicalize; the binder canonicalizes at resolve time).

**B.4** All call sites that previously used `Option<SheetId>` migrated cleanly: search for any remaining `Option<SheetId>` in AST/binder/calcgraph code that should be `SheetRef`.

### C. Lexer (W5-88)

**C.1** `Bang` token: emitted ONLY after a `SheetName` / `QuotedSheetName` / `Ident` that could be a sheet prefix? Or always, with the parser disambiguating? Verify what happens with `=A1!B2` (Excel rejects with `#NAME?`).

**C.2** `QuotedSheetName`: `''` escape handled. `'foo''bar'` → `SheetName("foo'bar")`. Verify `'foo` (unterminated) surfaces `LexError::UnterminatedQuotedSheetName` with correct byte position.

**C.3** `SheetName` lookahead: `Chars::clone()` for one-token peek. Verify the lookahead is consumed only when `!` follows; otherwise the original ident/bare-column flow proceeds. No double-consume bugs.

**C.4** Edge cases:
- `'Sheet 2'!A1` (space in sheet name) — should lex as QuotedSheetName + Bang.
- `Sheet1!A1` (unquoted) — should lex as SheetName + Bang (NOT Ident + Bang).
- `1Sheet!A1` (sheet name starts with digit) — Excel canon: must be quoted. Verify rejection at lex or parse time.
- `Sheet1` (alone, no `!`) — should lex unchanged (no SheetName promotion).

### D. Parser (W5-89)

**D.1** `apply_sheet_to_term`: handles every relevant `Expr` variant that can carry a sheet prefix (CellRef, RangeRef). Rejects sheet-prefix on inappropriate terms (Number, Function call) with `ParseError::DoubleSheetQualifier` or similar.

**D.2** `number_to_bare_row`: pre-conversion for `Sheet2!1:5` whole-row range case. Verify the conversion is reversible (round-trip prints).

**D.3** Cross-sheet range grammar per design § 10.5 (Codex HIGH-4 fix):
- Single-prefix normalization: `Sheet2!A1:B5` parses as `RangeRef { sheet: Name("Sheet2"), .. }`.
- Mixed-endpoint rejection: `Sheet1!A1:Sheet2!B5` MUST fail with a clean parse error (3D refs are not supported in this phase).
- Whole-column/whole-row both work with sheet prefix.

**D.4** `ParseError::DanglingBang` / `DoubleSheetQualifier`: error messages are user-facing + position-bearing.

**D.5** Aggregate-arg context preservation: a cross-sheet range inside `SUM(Sheet2!A1:A5)` — verify the parser still sets the aggregate-arg context. (The binder rejects this for now per W5-90 deferred test; verify Phase 4.7 doesn't surprise here.)

### E. Printer (W5-89)

**E.1** Sheet prefix emission for `Name` variant: emits exactly the canonical name + `!`. For `Id` variant: looks up the name (where?) and emits.

**E.2** Quoted-sheet round-trip: `'Q3 2025'!A1` must round-trip as `'Q3 2025'!A1` (with single quotes preserved). The printer needs to decide when to quote — minimum rule: any name with non-letter/digit chars or starting with a digit.

**E.3** `'` inside sheet name: `'foo''bar'` → escape via `''`. Round-trip lossless.

**E.4** Same-sheet refs: `SheetRef::Current` AND `SheetRef::Id(owning_sheet)` both emit WITHOUT a sheet prefix (post-bind state where the resolved id happens to match the owning sheet's id).

**E.5** Canonical spaces around binary operators (e.g. `Sheet2!A1 + 1`) — does the printer add spaces consistently as before? Tests at W5-89 already locked this; verify nothing regressed.

### F. Binder (W5-90)

**F.1** `SheetResolver` trait: `resolve_sheet(&str) -> Option<SheetId>`. `EmptySheetResolver` returns `None`. `Workbook` impl uses `sheet_id_by_name`.

**F.2** `bind_with_names_and_sheets`: the new entry point. Verify the legacy `bind_with_names` is unchanged behavior (workbook-scope only, empty sheet resolver). All callers migrated to the new entry point where cross-sheet support is needed.

**F.3** `resolve_sheet_ref`: `Name(N)` → `sheets.resolve_sheet(N)` → `BindError::UnknownSheet(N)` if `None`. `Current` → owning_sheet. `Id(s)` → `s` directly.

**F.4** `BindError::UnknownSheet`: clean diagnostic at bind time, before any runtime read. Verify the test `cross_sheet_formula_with_unknown_sheet` confirms `RuntimeError::Bind(UnknownSheet)` fires at `set_formula` return.

**F.5** `RangeRef` in binder: still rejected outside `Function` context per pre-existing rule. Cross-sheet doesn't change this — Phase 4.7 work.

### G. NameLookup chain (W5-92)

**G.1** `NameLookup` trait extended with `owning_sheet`. Three impls:
- `EmptyNameLookup` (test): ignores.
- `NameLookup for NameTable` (legacy): ignores.
- `NameLookup for Workbook` (new production): runs the two-tier chain per design § 7.3.

**G.2** `NameLookup for Workbook` two-tier chain:
- Tier 1: `self.sheet(owning_sheet).scoped_names().lookup_ci(name)`.
- Tier 2: `self.names().lookup_ci(name)`.
- Verify: from sheet 0 with scoped "Rate" = 0.21 and workbook "Rate" = 0.05 → tier 1 wins (0.21). From sheet 1 (no scoped "Rate") → tier 2 wins (0.05).

**G.3** Out-of-range `owning_sheet` defensive: returns workbook-scoped fallback rather than panicking. (Loader / test path.)

**G.4** Production call sites in `WorkbookRuntime`, `WorkbookTransaction`, `CalcgraphSession` switched from `wb.names()` to `wb`. Verify ALL sites switched — a missed call site would silently lose the sheet-scoped behavior for that path.

**G.5** Sheet-scoped name reserved-name guard: `is_reserved_name("AI")` fires on BOTH `set_name` and `set_scoped_name`. Verify both paths surface `NameTableError::Reserved`.

### H. Op log + replay (W5-91 + W5-92)

**H.1** `Op::SetName { scope: Option<SheetId>, .. }` extension: `#[serde(default, skip_serializing_if = "Option::is_none")]` keeps v3+old wire payloads deserializing unchanged. Verify a serialized v3 op (without `scope` field) round-trips through serde and lands at `scope: None`.

**H.2** Replay routing by scope: `None` → `workbook.set_name`. `Some(id)` → validate id → `sheet.set_scoped_name`. Unknown id → `ReplayError::InvalidSheet`. Reserved name → `ReplayError::NameRejected`.

**H.3** `Op::RenameSheet` replay: 3-case reconciliation per design § 3.3 (current==old apply; current==new noop; else mismatch). Verify the canonical comparison uses `Workbook::canonical_sheet_name` (NOT raw `String::eq`).

**H.4** `Op::RenameSheet` producer side in `WorkbookRuntime::rename_sheet`: emits a BatchCommit containing all `PutFormula` rewrites for stored formula text PLUS the `RenameSheet`. Verify the order: rewrites first, then rename. Verify the rewrite captures `iter_formulas` snapshot BEFORE mutation (no live-iter mutation hazard).

**H.5** `rewrite_formula_text_for_sheet_rename` defensive parse: corrupt/unparseable formula text leaves text unchanged. Verify the helper preserves the leading `=` if present.

**H.6** Producer-replay equivalence test: includes a `SetName` with `scope: None` (kept) AND now needs coverage for `scope: Some(_)`. Currently the equivalence test exercises a `scope: None`. Verify whether the scoped variant is tested elsewhere.

### I. Persistence schema v5 (W5-92)

**I.1** `WORKBOOK_SCHEMA_VERSION` 4 → 5 per Codex HIGH-2 fix. Verify all places that hard-coded `4` (other than the constant definition) are updated. Specifically: the `future_schema_version_rejected` test uses v6.

**I.2** `NamedEntry.scope: Option<u16>`. `#[serde(default, skip_serializing_if = ...)]`. Verify a v1-v4 TOML envelope WITHOUT the `scope` field on a NamedEntry deserializes cleanly to `scope: None`.

**I.3** Backwards-compat: v4 envelope with workbook-scoped names only loads on v5 reader without error. Sheet 0's `scoped_names` table stays empty.

**I.4** Forward-compat: a v5 reader REFUSES v6 via existing `UnsupportedSchema` path.

**I.5** Save-side determinism: scope-then-name sort. Verify the test `workbook_only_names_round_trip_serializes_without_scope_field` (asserts no `scope =` in TOML when no sheet-scoped names exist) covers the common case.

**I.6** Load-side error: `scope: Some(unknown_id)` → `MalformedName { name, reason }`. Verify the error message includes both the offending name AND the unknown sheet id.

**I.7** The `deny_unknown_fields` envelope-level attribute is still in place for `NamedEntry`. Confirm: adding a new field in v6 will require another bump (no silent forward-compat).

### J. Runtime sheet rename (W5-91)

**J.1** `WorkbookRuntime::rename_sheet` ordering: validate name → snapshot formulas → log BatchCommit (rewrite ops + RenameSheet) → apply rewrites → swap name → `plan_cache.clear()`. Verify the order: a failure between log-append and storage-mutation must not leave divergent state. Specifically: what happens if `oplog.append` succeeds but the subsequent storage write panics? (Probably can't happen given the validations, but verify.)

**J.2** `PlanCache::clear()`: full flush. Design doc § 10.5 / Codex MEDIUM-7 calls out a finer-grained `sheet_gen` counter as a future polish item. Verify the GAP is documented somewhere (known-gaps or follow-up file).

**J.3** Case-only rename (`Sheet1` → `SHEET1`): doesn't fail the dup check. Verify the formula-text rewrite still produces correct output (the printer should canonicalize to `SHEET1`).

**J.4** Cross-sheet formula text rewrite: `=SheetX!A1 + 1` becomes `=Renamed!A1 + 1` after `rename_sheet(0, "Renamed")`. Verify the rewrite leaves `Current` and `Id` SheetRefs untouched (only `Name` should match).

**J.5** Bind cache invalidation: any pre-rename bound plan that resolved `Name("SheetX") → Id(0)` is now stale (post-rename, "SheetX" no longer resolves). `plan_cache.clear()` should drop these.

### K. Runtime sheet-scoped name (W5-92)

**K.1** `WorkbookRuntime::set_sheet_scoped_name` ordering: validate sheet exists → reserved-name guard → append op → mutate. Verify a reserved name leaves the workbook unmutated AND the op log unmutated.

**K.2** `RuntimeError::InvalidSheet` for unknown sheet id BEFORE the op log append. Verify.

**K.3** Calcgraph hook: `on_set_name(name)` fired for sheet-scoped just like workbook-scoped. Over-invalidation is conservative; verify it doesn't break determinism.

**K.4** Round-trip: `set_sheet_scoped_name(s, "X", target)` then save → load preserves the scoping. Verify (this is the integration test in qbook_format).

### L. Cross-cutting / arch concerns

**L.1** Sheet rename + scoped names interaction: if a sheet has scoped names AND gets renamed, do those scoped names survive? They're keyed by `(sheet_id, name)` — sheet_id doesn't change on rename, so yes. Verify there's a test or note covering this.

**L.2** Cross-sheet formula text rewrite scope: does the rewrite walk through scoped names too? Currently rewrite walks `iter_formulas` (workbook-level). Scoped names with formula-text targets (`NamedTarget::Formula`) would NOT be rewritten by the current code path. Is this a gap?

**L.3** Workbook envelope envelope-level `deny_unknown_fields`: still in place for both `WorkbookEnvelope` and `NamedEntry`. Verify nothing in W5-92 weakened the strict policy.

**L.4** Phase 4.6 vs Phase 4.7 split: cross-sheet range as function arg `SUM(Sheet2!A1:A5)` deferred to Phase 4.7 (per W5-90's dropped test). Is this clearly documented (known-gaps / MASTER-PLAN)?

**L.5** PlanCache key: was it updated to include `sheet_gen` or workbook generation post-W5-91? Or does it rely solely on the wholesale `clear()` for rename invalidation?

**L.6** `is_reserved_name` (CORR-06 `AI`): currently only for workbook-scoped table. Codex MEDIUM in the design doc didn't flag this; verify with the impl that sheet-scoped check still fires through the same `NameTable::set` path → reserved guard.

**L.7** Hash stability: `SheetRef::Name(Arc<str>)` — two ARCs containing the same string should compare/hash equal. Verify the derive(Hash) on `Arc<str>` does what we expect. (Arc<str>'s Hash impl delegates to str's Hash, so yes.)
