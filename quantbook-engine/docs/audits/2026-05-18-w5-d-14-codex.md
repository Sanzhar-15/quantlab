# W5-D-14 XLSX Round-Trip Spine Audit - Codex

Date: 2026-05-18  
Scope: commits `c0a496e3627` through `13b64488dc0` (`crates/ql-io-xlsx`)  
Verdict: **NOT ship-ready as "round-trip spine closed."** The read/write cell skeleton exists, but the current exporter and reporting layer do not preserve the claimed workbook contract.

## Validation Performed

- Read scoped implementation files under `crates/ql-io-xlsx/`, `.plans/_active.md`, and `docs/process/audit-protocol.md`.
- Ran `cargo test -p ql-io-xlsx --lib -- --nocapture`: 44 passed.
- Ran `cargo test -p ql-io-xlsx --test calamine_smoke -- --nocapture`: 6 passed.
- Ran targeted compiled probes:
  - date1904 round-trip: re-import returned `Excel1900`.
  - error-value round-trip: `Value::Error(DivZero)` re-imported as `Text("#DIV/0!")`.
  - custom format round-trip: `FormatId(164)` re-imported as `None`.
  - defined-name fixture import: `workbook.names().len() == 0`.
  - table metadata NewWorkbook round-trip: table lookup after re-import was `false`.
  - formula-with-cached-value round-trip: re-import returned `formula=None, value=Number(5.0)`.
- Full `cargo test -p ql-io-xlsx` is currently polluted by an untracked local probe file (`crates/ql-io-xlsx/tests/zzz_audit_probe.rs`), so I used the tracked unit/integration targets plus focused probes.

## HIGH

### H-01

**Subject:** Formula cells with cached values lose their formula text during export

**Where:** `crates/ql-io-xlsx/src/write/umya_export.rs:86-94`, `crates/ql-io-xlsx/src/write/umya_export.rs:124-139`

**Detail:** `export_new_workbook` writes `cell.set_formula(...)` and then writes the cached value through `apply_value_to_cell`. In umya-spreadsheet 2.2.0, the public `set_value_number`, `set_value_bool`, and `set_value_string` paths remove any existing formula from the cell. A compiled probe with `put_at(C1, Number(5.0))` plus `put_formula(C1, "A1+B1")` exported and re-imported as `formula=None, value=Number(5.0)`. This means normal imported formula cells with cached values do not preserve formula text under the default `FormulaCachePolicy::WriteRecomputed`.

**Recommendation:** Use umya's formula-result API that does not clear formulas (`set_formula_result_default` / equivalent), or build a `CellValue` that sets formula and cached raw value without calling the public value setters. Add a tracked test for formula + cached number, bool, text, error, and blank cache.

**Severity rationale:** **Phase 4.11 ship blocker.** Formula text round-trip is an explicit W5-D-14 user-facing contract; the default export path destroys it for formula cells that also carry cached values.

### H-02

**Subject:** `date1904` imports but is never written on export

**Where:** `crates/ql-io-xlsx/src/lib.rs:145-148`, `crates/ql-io-xlsx/src/write/umya_export.rs:23-116`

**Detail:** Import parses `xl/workbook.xml` and calls `workbook.set_date_system(...)`, but NewWorkbook export creates a fresh umya workbook and never sets the workbook date system. A compiled probe built an `Excel1904` workbook, exported it, and re-imported `Excel1900`.

**Recommendation:** Write the workbook date system into the generated OOXML workbook properties, and add round-trip tests for `Excel1900` and `Excel1904` with actual serial date cells.

**Severity rationale:** **Phase 4.11 ship blocker.** Date serials become semantically different after round-trip; this is silent data corruption for 1904 workbooks.

### H-03

**Subject:** `ExportMode::UpdateOriginal` is not implemented, and export strictness/reporting is ignored

**Where:** `crates/ql-io-xlsx/src/lib.rs:240-259`, `crates/ql-io-xlsx/src/options.rs:67-72`, `crates/ql-io-xlsx/src/write/umya_export.rs:8-11`

**Detail:** The architecture and plan say imported XLSX round-trip should preserve opaque OOXML through `UpdateOriginal`, but `ExportMode::UpdateOriginal` returns a not-implemented engine error. NewWorkbook export is the only available writer and explicitly omits tables/styles/named ranges/opaque parts. `XlsxExportOptions::unsupported_policy` is never consumed, so even `UnsupportedPolicy::Strict` cannot stop lossy export. `XlsxExportReport.dropped_features` stays empty.

**Recommendation:** Either downgrade W5-D-14 to a lossy NewWorkbook cell-layer exporter in docs/commit messaging, or implement `UpdateOriginal` before claiming round-trip spine closure. Export must honor `UnsupportedPolicy::Strict` and populate `dropped_features` for every modelled or inventoried feature it cannot write.

**Severity rationale:** **Phase 4.11 ship blocker.** This breaks the central contract: import xlsx, recompute, export, re-import preserves workbook.

### H-04

**Subject:** XLSX-4-03 metadata round-trip is not shipped for names, tables, or formats

**Where:** `crates/ql-io-xlsx/src/lib.rs:77-78`, `crates/ql-io-xlsx/src/lib.rs:124-169`, `crates/ql-io-xlsx/src/read/workbook_xml.rs:17-23`, `crates/ql-io-xlsx/src/write/umya_export.rs:8-11`

**Detail:** Defined names are parsed into `WorkbookProperties` but never registered into `Workbook::names()` or sheet scoped name tables. A compiled probe against IronCalc `defined_names_for_unit_test.xlsx` imported `workbook.names().len() == 0`. Table metadata can be inserted/imported, but NewWorkbook export writes no table OOXML; a compiled table probe re-imported with `table_after=false`. Custom `FormatId(164)` round-tripped as `None`. Public rustdoc says "Sheets, cells, formulas, names, tables, formats all loaded," which is not true for names and not true for export.

**Recommendation:** Implement name registration/export, table export, and style/format export before marking XLSX-4-03 closed. Until then, change the public docs and active plan to say these are parsed scaffolds or deferred follow-ups, not preserved round-trip features.

**Severity rationale:** **Phase 4.11 ship blocker if W5-D-14 claims "round-trip spine closed."** This may be an acceptable follow-up only if the shipped contract is explicitly downgraded.

### H-05

**Subject:** Error values export as text, not OOXML errors

**Where:** `crates/ql-io-xlsx/src/write/umya_export.rs:119-139`

**Detail:** `Value::Error(e)` is written with `cell.set_value_string(e.sigil())`. That forces an OOXML string cell. A compiled probe re-imported `Value::Error(ErrorValue::DivZero)` as `Value::Text("#DIV/0!")`. The code comment says umya will produce `t="e"`, but the API being called is the string setter; umya has separate typed/error-guessing paths.

**Recommendation:** Use umya's `set_error(...)` or `set_value(...)` path that produces `CellRawValue::Error`, then assert the generated file re-imports as `Value::Error` for all supported Excel error sigils.

**Severity rationale:** **Phase 4.11 ship blocker.** Error cells are part of the stated value round-trip surface; text-vs-error changes formula semantics on re-import.

## MEDIUM

### M-01

**Subject:** Table import maps workbook-order index to `sheetN.xml.rels` instead of following workbook relationships

**Where:** `crates/ql-io-xlsx/src/read/tables_import.rs:39-59`

**Detail:** `import_tables` assumes sheet index `0` uses `xl/worksheets/_rels/sheet1.xml.rels`, index `1` uses `sheet2.xml.rels`, etc. OOXML does not guarantee workbook tab order, `sheetId`, relationship id, and physical `sheetN.xml` numbering stay aligned after sheet deletion/reordering or producer-specific output. The parser already reads `workbook.xml` sheet `r:id`, but that metadata is unused.

**Recommendation:** Resolve workbook sheet parts through `xl/_rels/workbook.xml.rels`, then derive each worksheet rels path from the actual sheet part path.

**Severity rationale:** Not always hit by simple fixtures, but common enough in real XLSX files to silently attach table metadata to the wrong sheet or skip it.

### M-02

**Subject:** Table XML parser silently accepts malformed required numeric attributes and invalid table metadata

**Where:** `crates/ql-io-xlsx/src/read/tables_xml.rs:93-120`, `crates/ql-io-xlsx/src/read/tables_xml.rs:177-199`, `crates/ql-io-xlsx/src/read/tables_import.rs:63-64`

**Detail:** `id`, `headerRowCount`, `totalsRowCount`, and `tableColumn/@id` parse failures fall back to `0`/defaults. The parser does not validate `tableColumns/@count`, column count vs `ref` width, duplicate/zero column ids, duplicate table names, or table footprint bounds. `TableTable::insert` overwrites on canonical-name collision, so malformed duplicate tables silently lose one table.

**Recommendation:** Treat malformed numeric required attributes as `MalformedOoxml`, validate footprint with `TableMetadata::validate_footprint_bounds`, reject duplicate canonical table names, and validate column roster shape before insertion.

**Severity rationale:** Corrupt OOXML should surface visible errors at the XLSX trust boundary; current behavior silently mutates table structure.

### M-03

**Subject:** Style import is format-table only; per-cell style application is absent and some `cellXfs` forms are missed

**Where:** `crates/ql-io-xlsx/src/read/styles_import.rs:4-12`, `crates/ql-io-xlsx/src/read/styles_xml.rs:115-135`, `crates/ql-io-xlsx/src/lib.rs:159-169`

**Detail:** Custom numFmts are registered, but worksheet `<c s="N">` style ids are not mapped into the sheet format overlay. Also, `styles_xml` only records `<xf/>` as `Event::Empty`; an `<xf>...</xf>` with child `alignment` or `protection` inside `<cellXfs>` is treated as `Event::Start` and its `numFmtId` is not recorded.

**Recommendation:** Parse worksheet cell style ids and apply `FormatId`s to the per-sheet overlay. Parse `xf` attributes on both `Start` and `Empty` events, with tests for alignment/protection child elements.

**Severity rationale:** The current code is useful scaffolding, but it does not support the documented "formats survive round-trip where supported" claim.

### M-04

**Subject:** Feature inventory is incomplete, content-string based, and does not populate per-feature report records

**Where:** `crates/ql-io-xlsx/src/read/feature_inventory.rs:36-83`, `crates/ql-io-xlsx/src/report.rs:18-20`

**Detail:** The scanner detects a small set of path prefixes and raw substrings. It misses sheet-view metadata such as freeze panes, split panes, and no-gridline state; compiled probes showed `dynamic_arrays.xlsx`, `freeze.xlsx`, and `split.xlsx` inventories as `{}`. It also misses workbook `extLst`/calc features and many common OOXML part families (charts, slicers/timelines, threaded comments/persons, connections/queryTables). Namespaced worksheet tags can be missed by `content.contains("<dataValidations")` style checks. `report.unsupported` remains empty, so callers get counts without locations.

**Recommendation:** Parse `[Content_Types].xml` and worksheet XML with quick-xml local-name matching, record `UnsupportedFeature` entries with part and detail, and add golden inventory tests for the IronCalc UI-artifact fixtures listed in `.plans/_active.md`.

**Severity rationale:** XLSX-4-04 requires visible unsupported-feature reporting; current inventory still produces false-clean reports for real metadata that export drops.

### M-05

**Subject:** Strict unsupported-feature error is nondeterministic and loses location detail

**Where:** `crates/ql-io-xlsx/src/lib.rs:174-192`, `crates/ql-io-xlsx/src/model.rs:34-51`

**Detail:** Strict mode picks `feature_inventory.counts.iter().next()` from a `HashMap`, so the reported first feature is nondeterministic. The error always uses `part: "workbook"` and points users to an import report that is not returned on `Err`.

**Recommendation:** Store inventory in deterministic order or sort before choosing the first error. Return the actual first unsupported record with part/detail, or add an error type that carries the full inventory.

**Severity rationale:** Strict mode is the fidelity-verification path; nondeterministic and under-specified errors reduce its usefulness in CI and audits.

### M-06

**Subject:** BestEffort recompute does not catch panics at the xlsx trust boundary

**Where:** `crates/ql-io-xlsx/src/read/convert.rs:113-146`

**Detail:** `recompute_loaded_workbook` calls `WorkbookRuntime::recompute_all()` directly. It translates returned failures into `FormulaImportFailure`, but if the runtime panics on an adversarial formula or engine bug, the panic propagates through the import API. That contradicts the "BestEffort reports failures and keeps imported cached values" behavior.

**Recommendation:** Wrap recompute in `catch_unwind` at the XLSX boundary and translate panics into an `XlsxError::Engine` or a workbook-level warning depending on `RecomputeMode`.

**Severity rationale:** Runtime panics should not escape untrusted XLSX import paths.

### M-07

**Subject:** OOXML parsers silently swallow malformed attributes

**Where:** `crates/ql-io-xlsx/src/read/workbook_xml.rs:132-188`, `crates/ql-io-xlsx/src/read/rels.rs:80-95`, `crates/ql-io-xlsx/src/read/styles_xml.rs:154-180`

**Detail:** Multiple parsers use `attributes().with_checks(false).flatten()` plus `unescape_value().unwrap_or_default()`. This drops malformed attributes instead of surfacing XML/OOXML errors. In workbook defined names, a malformed `localSheetId` is silently treated as workbook-scoped. In rels parsing, a relationship with missing `Type`/`Target` but nonempty `Id` is accepted.

**Recommendation:** Iterate attributes explicitly, map attribute parse/unescape failures to `XmlParse`/`MalformedOoxml`, and only apply defaults where OOXML defines a default.

**Severity rationale:** This is a defense-in-depth violation in a file-format trust boundary.

### M-08

**Subject:** Workbook XML sheet metadata is parsed but unused; visibility and reconciliation are lost

**Where:** `crates/ql-io-xlsx/src/read/workbook_xml.rs:31-56`, `crates/ql-io-xlsx/src/lib.rs:124-157`

**Detail:** The parser captures sheet order, `sheetId`, `r:id`, and visibility state, but import uses calamine `sheet_names()` for storage and only applies `date_system` from `WorkbookProperties`. Hidden/veryHidden state is dropped without inventory warning, and there is no reconciliation check despite `XlsxError::Reconciliation` existing for hybrid-reader disagreement.

**Recommendation:** Make workbook.xml sheet metadata authoritative for sheet part resolution and unsupported visibility reporting. Add reconciliation tests for workbook order, hidden sheets, and nontrivial sheet part names.

**Severity rationale:** Sheet identity and visibility are workbook structure, not cosmetic metadata, and currently they can silently diverge.

### M-09

**Subject:** NewWorkbook export is dense over sheet bounds and can hang on sparse far-boundary cells

**Where:** `crates/ql-io-xlsx/src/write/umya_export.rs:75-109`

**Detail:** The exporter iterates every row/column in `sheet.bounds()`. A workbook with a single populated cell at `MAX_ROW, MAX_COLUMN` forces roughly 17 billion loop iterations. This can occur from a valid sparse XLSX boundary cell and makes export effectively non-terminating.

**Recommendation:** Iterate sparse column/cell storage rather than rectangular bounds, and separately merge formula-only cells. Add a boundary-cell export test that completes quickly.

**Severity rationale:** Not a semantic corruption bug, but a valid workbook can trigger severe performance failure.

### L-08

**Subject:** Zero-sheet export has no explicit policy

**Where:** `crates/ql-io-xlsx/src/write/umya_export.rs:43-116`

**Detail:** A probe exporting `Workbook::new()` returned `Ok` and re-imported as a zero-sheet workbook. Excel workbooks normally require at least one sheet, and the current API does not say whether zero-sheet xlsx output is valid or intentionally supported.

**Recommendation:** Decide policy: reject zero-sheet export with `XlsxError::Export`, or create a default empty sheet. Add a test either way.

**Severity rationale:** Edge-case correctness issue; not the main W5-D-14 contract failure.

### L-09

**Subject:** Comments path prefix can overmatch future comment-related parts

**Where:** `crates/ql-io-xlsx/src/read/feature_inventory.rs:36-43`

**Detail:** The scanner records comments for any zip path starting with `xl/comments`, which can include adjacent comment-history/thread/person metadata depending on producer/version. Some of those should probably map to distinct unsupported kinds or details.

**Recommendation:** Match exact known part patterns (`xl/comments*.xml`, threaded comments, persons) and record distinct details.

**Severity rationale:** Low current impact, but it will make strict-mode diagnostics noisy as fixture coverage grows.

## Notes

- The calamine-to-Quantbook coordinate translation is correct for calamine 0.34: `Range::used_cells()` returns range-relative coordinates, and the code adds `range.start()` before writing to storage.
- The Quantbook-to-umya coordinate conversion (`col + 1`, `row + 1`) is correct for the storage bounds.
- The major failures are not coordinate off-by-ones; they are fidelity-contract gaps and lossy writer behavior.
