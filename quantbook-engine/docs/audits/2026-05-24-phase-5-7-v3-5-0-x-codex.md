# Phase 5.7 V3.5.0.X Termination Audit - Codex Lane A

Date: 2026-05-24
Lane: A - protocol/correctness over the V3.5 engine + IDE binding surface
Engine branch: `feat/quantbook-engine` at `1792a470e40`

## 1. Executive Summary

**Result: FAIL.**

The V3.5 surface is broadly coherent, and most of the WorkbookSnapshot, sheet-op, format-cache, and render-migration implementation matches the intended shape. However, I found four HIGH findings that must close in-cycle before V3.5 can terminate:

1. Partial-invalidate undo/redo is unsafe when a remote op is visible after the local op being undone/redone. The shrink/grow-by-1 guard does not force a full rebuild in that case, and I reproduced stale cache state through the native binding.
2. `workbookSnapshot()` discards the repaired materialized `Workbook` and serializes formulas from `last_snapshot`, so the documented rename-repair guarantee for `CellSnapshotJson.formula` is false.
3. Sheet management commands mutate the session but do not repaint the affected panel, while § 4.1.z5 live smoke and reactive-title claims require immediate visible updates.
4. The mid-edit-render guard skips a merged render but does not record a pending repaint, so the "deferred render fires on the next tick" guarantee is false.

One LOW doc hygiene issue is also noted: IDE TS comments still mention `null` for optional napi fields even though the code/tests correctly use absent/`undefined`.

## 2. § 1 - WorkbookSnapshot Serialization Correctness

`CollabSession::workbook_snapshot()` does route through `inner.rebuild_workbook(&default_registry())`, then uses the rebuilt `Workbook` for `sheet_count`, `sheet_display_order`, tombstone state, and sheet names ([crates/ql-bindings-node/src/lib.rs:1523](../../crates/ql-bindings-node/src/lib.rs#L1523), [crates/ql-bindings-node/src/lib.rs:1526](../../crates/ql-bindings-node/src/lib.rs#L1526), [crates/ql-bindings-node/src/lib.rs:1544](../../crates/ql-bindings-node/src/lib.rs#L1544), [crates/ql-bindings-node/src/lib.rs:1565](../../crates/ql-bindings-node/src/lib.rs#L1565), [crates/ql-bindings-node/src/lib.rs:1571](../../crates/ql-bindings-node/src/lib.rs#L1571)). Cells are serialized from `inner.snapshot_cells(sheet_id)`, not from the materialized `Workbook` ([crates/ql-bindings-node/src/lib.rs:1580](../../crates/ql-bindings-node/src/lib.rs#L1580)).

The JSON structs are lossless against the current `CellState` cache:

- `CellValueJson` covers all `CellWireValue` variants, including `Pending`, and only sets the active payload ([crates/ql-bindings-node/src/lib.rs:413](../../crates/ql-bindings-node/src/lib.rs#L413), [crates/ql-bindings-node/src/lib.rs:421](../../crates/ql-bindings-node/src/lib.rs#L421)).
- `CellSnapshotJson` carries `row`, `col`, `value`, `formula`, and `format` ([crates/ql-bindings-node/src/lib.rs:551](../../crates/ql-bindings-node/src/lib.rs#L551)).
- `SheetSnapshotJson` and `WorkbookSnapshotJson` are straightforward `Vec` wrappers over sheet/cell data ([crates/ql-bindings-node/src/lib.rs:581](../../crates/ql-bindings-node/src/lib.rs#L581), [crates/ql-bindings-node/src/lib.rs:613](../../crates/ql-bindings-node/src/lib.rs#L613)).
- `FormatIdJson` handles both `Builtin(u32)` and `Custom(PeerId, u32)`, widening `PeerId.0` to JS BigInt ([crates/ql-bindings-node/src/lib.rs:492](../../crates/ql-bindings-node/src/lib.rs#L492), [crates/ql-bindings-node/src/lib.rs:504](../../crates/ql-bindings-node/src/lib.rs#L504)).

The `Option::None -> absent JS property` invariant is implemented in the Rust shape and pinned by IDE tests for non-active `CellValueJson` payloads, pure `PutValue` `formula`, and absent `format` ([extensions/quantlab/test/quantbook-roundtrip.test.ts:4421](../../../../quantlab/extensions/quantlab/test/quantbook-roundtrip.test.ts#L4421), [extensions/quantlab/test/quantbook-roundtrip.test.ts:4437](../../../../quantlab/extensions/quantlab/test/quantbook-roundtrip.test.ts#L4437), [extensions/quantlab/test/quantbook-roundtrip.test.ts:5579](../../../../quantlab/extensions/quantlab/test/quantbook-roundtrip.test.ts#L5579)). The TS interfaces use optional fields, but some comments still say `null`; see LOW finding A-LOW-1.

Display order and tombstones are applied in the correct order: `sheet_display_order().to_vec()` is resolved first, missing IDs are defensively appended, then tombstoned IDs are filtered ([crates/ql-bindings-node/src/lib.rs:1544](../../crates/ql-bindings-node/src/lib.rs#L1544), [crates/ql-bindings-node/src/lib.rs:1546](../../crates/ql-bindings-node/src/lib.rs#L1546), [crates/ql-bindings-node/src/lib.rs:1560](../../crates/ql-bindings-node/src/lib.rs#L1560), [crates/ql-bindings-node/src/lib.rs:1565](../../crates/ql-bindings-node/src/lib.rs#L1565)). **Finding A-HIGH-2:** the rebuilt `Workbook` discard is not safe for the documented formula-repair contract. `repair_sheet_rename_chain` mutates formulas in the materialized `Workbook` ([crates/ql-collab/src/repair.rs:345](../../crates/ql-collab/src/repair.rs#L345), [crates/ql-collab/src/repair.rs:363](../../crates/ql-collab/src/repair.rs#L363)), but `workbookSnapshot()` serializes formula text from the unrepaired `last_snapshot` cache ([crates/ql-bindings-node/src/lib.rs:1580](../../crates/ql-bindings-node/src/lib.rs#L1580), [crates/ql-bindings-node/src/lib.rs:1587](../../crates/ql-bindings-node/src/lib.rs#L1587)). ## 7. § 6 - Partial-Invalidate Undo

`invalidate_cell` itself follows the intended shape: it removes only the target key, walks the log, collects effects through the same helper as full rebuild, applies only target-cell effects into a local map, and re-inserts if a surviving state exists ([crates/ql-collab/src/session.rs:1137](../../crates/ql-collab/src/session.rs#L1137), [crates/ql-collab/src/session.rs:1147](../../crates/ql-collab/src/session.rs#L1147), [crates/ql-collab/src/session.rs:1157](../../crates/ql-collab/src/session.rs#L1157), [crates/ql-collab/src/session.rs:1169](../../crates/ql-collab/src/session.rs#L1169), [crates/ql-collab/src/session.rs:1180](../../crates/ql-collab/src/session.rs#L1180)).

The side-by-side tests cover the advertised local shapes: PutValue, PutFormula, ClearFormula, SetCellFormat, AddSheet fallback, all-cell-keyed BatchCommit, redo, multi-cell BatchCommit, and classifier units ([crates/ql-collab/src/session.rs:3910](../../crates/ql-collab/src/session.rs#L3910), [crates/ql-collab/src/session.rs:3963](../../crates/ql-collab/src/session.rs#L3963), [crates/ql-collab/src/session.rs:3978](../../crates/ql-collab/src/session.rs#L3978), [crates/ql-collab/src/session.rs:4005](../../crates/ql-collab/src/session.rs#L4005), [crates/ql-collab/src/session.rs:4037](../../crates/ql-collab/src/session.rs#L4037), [crates/ql-collab/src/session.rs:4061](../../crates/ql-collab/src/session.rs#L4061)).

**Finding A-HIGH-1:** the mixed-remote-op safety assumption is false. `undo()` captures `self.log.iter().last()` before undo, then uses partial invalidation whenever visible length shrank by exactly one ([crates/ql-collab/src/session.rs:2359](../../crates/ql-collab/src/session.rs#L2359), [crates/ql-collab/src/session.rs:2388](../../crates/ql-collab/src/session.rs#L2388)). If a remote op is visible after the local op being undone, visible length still shrinks by exactly one, but the captured last op is the remote op. The code invalidates the remote cell and leaves the undone local cell stale. I reproduced this through the native binding:

```text
same session after undo [ [ 0, 0, 10 ], [ 1, 0, 20 ] ]
reborn full rebuild     [ [ 1, 0, 20 ] ]
```

Scenario: base sheet is imported into A and B; A writes `(0,0)=10`; B writes `(1,0)=20`; A merges B; A calls `undo()`. The same-session `workbookSnapshot()` still shows A's undone cell, while reloading A's exported bytes into a fresh session, which rebuilds the cache, removes it. This directly contradicts § 4.1.z5's claim that the shrinkage-by-exactly-1 check defensively falls back in the mixed-remote-ops case ([docs/architecture/ide-consumer-contract.md:1483](../architecture/ide-consumer-contract.md#L1483)). `redo()` has the symmetric risk because it captures post-redo visible last op under a grow-by-1 check ([crates/ql-collab/src/session.rs:2437](../../crates/ql-collab/src/session.rs#L2437)).

## 10. Closing Thoughts / V3.5 Architectural Observations

V3.5's direction is sound: a flattened WorkbookSnapshot, stable sheet IDs, tombstones, display-order overlay, and per-field `CellState` make the surface much more usable for the IDE. The main correctness problems are boundary problems:

- The cache and the materialized/repaired `Workbook` are now two sources of truth. `workbookSnapshot()` currently mixes them: Workbook for sheet metadata, cache for cells. That is fine for values/formats, but not for formula text after rename repair.
- Partial-invalidate needs the actual undo/redo target, not a heuristic based on visible last op. The heuristic is correct only in purely local frontier cases.
- IDE render scheduling needs an explicit dirty flag. Once a remote blob is drained, future poll ticks cannot infer that a skipped render is still owed.
- Sheet commands need a repaint trigger if they are the user-facing substitute for sheet tabs in V3.5.

I would not start V3.6 entry work until the four HIGH findings above are closed and re-audited.
