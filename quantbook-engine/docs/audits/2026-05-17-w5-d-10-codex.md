### LOW-1

Subject: Dotted-name e2e comment overstates lexer coverage.

Where: `crates/ql-exec/tests/region_mul2_e2e.rs:573`

Detail: The new dispatcher smoke test correctly proves that `ERF.PRECISE`
and `ERFC.PRECISE` route through parser/dispatcher/registry lookup, but the
comment says the aliases exercise the W5-D-2 digit-leading-segment lexer path.
These function names are regular letter-leading dotted identifiers, so the
test does not cover the digit-leading dotted-name extension. Behavior is
correct; the issue is only the explanatory comment.

Recommendation: Reword the comment to say the test covers regular dotted
identifier parsing plus case-insensitive registry lookup, and remove the
W5-D-2 digit-leading reference.

Severity rationale: Documentation/test-comment only. It can mislead future
closeout audits about parser coverage, but it does not affect runtime behavior
or Excel compatibility.
