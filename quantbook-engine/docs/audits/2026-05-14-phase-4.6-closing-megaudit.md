## Consolidated findings

### HIGH (closure-blocking)

#### HIGH-1 — sheet-name validation bypass at storage + runtime + replay
**Verdict:** Codex A FAIL HIGH; Sonnet A.4 FAIL MEDIUM (rated lower because rename validates; Codex looked deeper and saw the storage layer's silent acceptance).

**Citations:**
- `crates/ql-storage/src/workbook.rs:463` — `Workbook::add_sheet` skips `validate_sheet_name`.
- `crates/ql-storage/src/workbook.rs:485` — `add_sheet_with_chunk_rows` ditto.
- `crates/ql-exec/src/workbook_runtime.rs:781` — `WorkbookRuntime::add_sheet` validates `chunk_rows` and `sheet_count` but skips name validation.
- `crates/ql-oplog/src/replay.rs:298` — `Op::AddSheet` replay calls storage directly with no name check.

**Repro:** `wb.add_sheet("Sheet1")` then `wb.add_sheet("SHEET1")` succeeds and produces two sheets that conflict under canonical comparison. Similarly `wb.add_sheet("Bad:Name")` enters storage despite the reserved-char rule.

**Closure:** validate at all 3 boundaries. Make storage `_with_chunk_rows` return `Result<SheetId, SheetNameError>`. Pre-validate at runtime + replay so bad inputs return clean errors before any op-log/state mutation.

#### HIGH-2 — `PlanCache` doesn't invalidate on sheet-scoped name change
**Verdict:** Codex G FAIL HIGH (Codex-only finding; Sonnet rated G all PASS).

**Citations:**
- `crates/ql-exec/src/workbook_runtime.rs:495` — cache key includes only `workbook.names().generation()`.
- `crates/ql-exec/src/workbook_runtime.rs:734` — `set_sheet_scoped_name` mutates the sheet's scoped table but doesn't touch the cache.

**Repro:** Bind `=Rate` on sheet 0 when workbook-scoped `Rate = 0.05` exists (cache stores plan with workbook-scoped resolution). Call `set_sheet_scoped_name(0, "Rate", 0.21)`. Recompute reads the cached plan with the workbook-scoped value (0.05) — never re-binds against the new sheet-scoped `Rate`.

**Closure:** call `self.plan_cache.clear()` at the end of `set_sheet_scoped_name`, matching the W5-91 rename pattern. Per-sheet generation is design § 10.5 / Codex MEDIUM-7 future polish; full flush is acceptable at edit rate.

### MEDIUM

#### MEDIUM-1 — Printer panics on `SheetRef::Id`
**Verdict:** Codex E FAIL MEDIUM; Sonnet E.1/E.4 FAIL MEDIUM (both auditors converged).

**Citation:** `crates/ql-formula-syntax/src/printer.rs:82`.

**Repro:** Any caller that binds an AST (resolving `Name → Id`) then prints will panic. Currently safe because `rewrite_sheet_name_in_expr` operates on pre-bind ASTs. Latent footgun.

**Closure:** improve the panic message + add a doc note that print is pre-bind-only by contract; resolver-aware print is a future polish item.

#### MEDIUM-2 — `NamedTarget::Formula` not rewritten on sheet rename
**Verdict:** Codex J MIXED MEDIUM; Sonnet L.2 + L.3 FAIL MEDIUM.

**Citation:** `crates/ql-exec/src/workbook_runtime.rs:855`.

**Repro:** Register `wb.set_name("Profit", NamedTarget::Formula("Sheet1!A1 - 1"))`. Rename `Sheet1 → Renamed`. Stored formula text on cells gets rewritten correctly; the `Profit` named-formula text still says `Sheet1!A1 - 1` and will fail at next bind.

**Closure:** file as known-gap entry (named-formula resolution itself is Phase 4+ work; binder currently rejects `NamedTarget::Formula` in scalar context anyway). Deferred from W5-93 to a future polish item.

#### MEDIUM-3 — Producer-replay equivalence missing scope coverage
**Verdict:** Codex H/M MIXED MEDIUM; Sonnet M.2 + M.3 LOW (closer reading shows the comparator gap is medium-severity).

**Citations:**
- `crates/ql-oplog/tests/producer_replay_equivalence.rs:55` — realistic sequence only exercises `scope: None`.
- `crates/ql-oplog/tests/producer_replay_equivalence.rs:236` — `assert_workbooks_observationally_equal` doesn't compare `scoped_names`.

**Closure:** add a `SetName { scope: Some(_), .. }` op to the realistic sequence; extend the comparator to walk each sheet's `scoped_names()`.

**Citations:**

### LOW

#### LOW-1 — Lexer accepts `A1!B2`
**Verdict:** Codex C LOW; Sonnet C.4 PASS (by-design documented limitation).

**Citation:** `crates/ql-formula-syntax/src/lexer.rs` — `try_lex_sheet_name_prefix` doesn't reject A1-shaped sheet names.

**Status:** Excel rejects `A1!B2` as `#NAME?`. Quantbook accepts it; the binder would then try to resolve sheet "A1" (likely failing with `BindError::UnknownSheet`). Not a security issue. File as known-divergence entry.
