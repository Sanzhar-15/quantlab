# Opus audit — Tier C1 cycle detection

## Severity-tagged findings

### H-1 — bind-failed nodes may enter cycled set (LOW practical impact)

File: `crates/ql-exec/src/calcgraph_session.rs` lines 892–921.

`rebuild_from_workbook`'s pre-pass inserts a `CellNode` for every
formula (line 893) BEFORE bind attempts. If bind fails (line 914)
the node remains in the session but with **zero edges** (extract
is skipped). In `recompute_all` line 3022, this node is marked
dirty and passed to Tarjan. Tarjan, however, only emits a node in
`cycled` if it is part of a non-trivial SCC or has a self-loop —
a zero-edge node has neither, so it is correctly excluded.

The audit flags this as ambiguous *intent* rather than a real
correctness bug. Closure: documented in-code at the top of
`recompute_all`'s docstring (post-audit closure comment for
*Opus H-1*).

### M-1 — test coverage gaps for richer cycle topologies

File: `crates/ql-exec/src/workbook_runtime.rs` lines 4620–4719.

The four pre-audit tests cover only:
- 1-cycle (direct self-reference).
- 2-cycle (A1↔B1).
- Acyclic + 1-cycle mix.
- Idempotency across repeated calls.

Missing direct coverage for: 3-cycle (A→B→C→A), self-referential
`SUM(A:A)` (range self-loop via `supplemental`), named-range cycle
(`Sales` = A1:A10, A1 = `=SUM(Sales)`), cross-sheet cycle, table-
column cycle.

Status: **deferred to Tier C1-followup** in v2 backlog (closure
in this commit added two NEW tests for higher-priority Codex H-1
and H-2 cases — the topology coverage is lower priority and
amounts to ~6 more tests).

### M-2 — double-parse cost on cold load

File: `crates/ql-exec/src/workbook_runtime.rs` line 3008 + 3055.

`rebuild_from_workbook` parses every formula once during the
session build (via `bind_text`); the eval loop below parses each
again via `try_recompute_one_cached`. For a 10K-formula `.qbook`
load, this is 2× the lex+parse cost on the cold path.

The patch's comment acknowledges the tradeoff but does not
measure it or explore plan-cache reuse. Closure path: bench on a
real 10K-formula workbook; if the measured cost is significant
(> 5% of total load time), thread the rebuild's bound plans
forward into the runtime's `PlanCache` so the eval loop reuses
the binds.

Status: **deferred to v2 backlog** (Tier C1-perf followup).

### M-3 — spill anchor in cycle untested

File: `crates/ql-exec/src/workbook_runtime.rs` lines 3050–3052
(pre-pass write site).

Original concern: if a spill-anchor formula is part of a cycle,
the patch writes `#CIRC!` to the anchor via `put_computed_at` but
does not run the spill cleanup pipeline. Old spill body cells
(A2, A3 from a prior `SEQUENCE(3)` spill at A1) could survive.

**Closed in this commit** alongside Codex H-2 with the
`clear_spill_if_present` call in the pre-pass + regression test
`recompute_all_clears_stale_spill_when_anchor_becomes_circular`.

### L-1 — comment overpromises "matches recompute_dirty's contract"

File: `crates/ql-exec/src/workbook_runtime.rs` line 3046 (original
pre-audit text).

Pre-audit comment: "Matches `recompute_dirty`'s contract (cycled
cells contribute to `attempted` but not `succeeded`)." This is
imprecise because `recompute_dirty` also implements VEQ short-
circuit and other ordering logic that `recompute_all` does not.

**Closed**: comment rewritten to say "Matches `recompute_dirty`'s
cycled-cell accounting" with an explicit note that VEQ logic is
intentionally absent.

### L-2 — `#[non_exhaustive]` interaction OK

File: `crates/ql-exec/src/workbook_runtime.rs` line 3070 (the
`if let RuntimeError::Bind(...)` pattern).

`RuntimeError` is `#[non_exhaustive]` (Tier A shipped earlier).
Pattern uses partial-match style with explicit `else` fallback;
no breakage. No action required.

## OK confirmations

- Ephemeral session is isolated and dropped before any workbook
  mutation. Aggregate cache is cleared at end of rebuild
  (`calcgraph_session.rs:934`); no spillover.
- `cell_node_for` gracefully handles formulas with no node
  (line 3022 checks `is_some()` before mark_dirty).
- `ql-exec/src/loader.rs::load_workbook_and_recompute` calls
  `recompute_all` directly (line 63), so `.qbook` load path
  inherits the fix transparently.
- `replay_into` in `ql-oplog/src/replay.rs` does NOT call
  `recompute_all` (only applies ops, lines 296–308); however,
  callers of `replay_into` are documented (line 17) to call
  `recompute_all` separately. **Codex M-2 expands on this point —
  see consolidated closure doc.**
- Idempotency test (lines 4704–4719) correctly exercises the
  repeated-call stability invariant.
