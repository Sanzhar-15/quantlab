# Lane 4 — Opus concurrency / lifecycle / soundness

Verdict: **SHIP** · HIGH 0 · MED 0 (the aggregate-stall MED is pre-existing-documented) · LOW 3 · 30 tool uses / 101.4k tokens. Built ql-exec + ql-udf + ql-bindings-node on the Mac host (compile) and ran the 14 UDF lib tests (pass).

## Point-by-point (verbatim verdicts)
1. **Send / !Sync — CLEAN.** `+ Send` at every `dyn UdfWorker` site (session.rs field + setter; env.rs trait method + field + ctor + impl; workbook_runtime field + both `with_session_state*`; transaction.rs field + `with_optional_oplog`). `RefCell<Box<dyn UdfWorker + Send>>: Send`, `!Sync`. The napi `assert_send`/`assert_sync` gates compile. `grep` for `rayon|par_iter|thread::spawn|scope|crossbeam` across eval crates → zero in eval paths; `simd.rs` never references `CellEnv`/`WorkbookEnv`. No parallel code carries a worker-bearing env. (Filed-forward: when the rayon layer lands, a worker-bearing `&WorkbookEnv` must never cross into a parallel closure.)
2. **Worker death / respawn during multi-cell recompute — CLEAN.** `ProcessWorker::call` self-contained; the `borrow_mut` is scoped to one `call()`; respawn happens inside that call under its own borrow; no borrow held across respawn; `spawn()` assigns `self.proc` only on full success. Cascading N×30s is liveness, accurately documented.
3. **Drop / teardown — CLEAN.** Single-threaded eval; a borrow can't be live while the session drops on the same thread. `RefCell` has no poison; an unwind drops the guard via RAII. `WorkerProcess::drop` kills+reaps + detaches the reader (6.4-3b). `set_udf_worker` is `&mut self`, can't race eval.
4. **FaultGuard panic-freedom across FFI — CLEAN.** Every panic site enumerated (2 `unreachable!`, boundary `.expect`, `borrow_mut`, codec, `ArrayValue::new`, `grid.get`) provably unreachable or `Result`-returning. A reader-thread panic drops the `tx` → `Disconnected` → `WorkerDied` → `#CALC!`, never propagates to the recalc thread. Real dispatch is panic-free → the catch-unwind-free napi boundary is never crossed by a dispatch panic.
5. **Deadlock / lock-ordering — CLEAN** (aggregate-stall is the known, documented MED). The 30s call runs under the napi `parking_lot::Mutex`; the worker is a separate process whose reader thread touches only its own mpsc and never re-acquires the engine mutex or re-enters eval. No deadlock; only the documented liveness stall.
6. **transaction.rs worker threading — CLEAN.** `commit(self)` destructures `workbook`/`udf_worker` from disjoint fields; pass-2 reborrows `&mut Workbook` as `&Workbook` for eval while holding the worker `&RefCell`, sequential, no aliasing; `'a` ties worker+workbook+oplog to one scope; `validate.rs` forwards correctly.

## LOW findings
- **LOW-1** respawn handshake budget can be starved by the per-call deadline (`process.rs:304` `min(handshake_timeout, deadline_at-now)`) — a respawn of a healthy python near the deadline could spuriously time out → `WorkerDied`. Near-impossible; opportunistic fix (a floor) suggested.
- **LOW-2** load/import recompute path has no worker (`loader.rs:62`, `xlsx_recompute.rs:38`) → UDF formulas load as `#CALC!`. Consistent with injection-ordering model; filed-forward for the 6.4-3d host bridge.
- **LOW-3** large-range arg materializes the full grid into one `Vec<Value>` + clone before the 64 MiB frame cap helps. Resource concern, not soundness. Filed-forward.
