## What to look for

### Correctness

1. **10-digit two's-complement canon per base**:
   - Binary: `[-512, 511]`, wrap at `2^10 = 1024`.
   - Octal: `[-2^29, 2^29-1]`, wrap at `8^10 = 2^30`.
   - Hex: `[-2^39, 2^39-1]`, wrap at `16^10 = 2^40`.
   - Verify constants match: `BIN_MAX=1024`, `OCT_MAX=2^30=1073741824`,
     `HEX_MAX=2^40=1099511627776`.

2. **Negative DEC2* encoding**: value + radix_max → format. Negative
   always produces 10-digit output (high digit signals sign).
   Verify all 3 fns implement this correctly.

3. **Positive DEC2* with places**: zero-pad to `places` width; if
   `places < result.len()` → `#NUM!`. Verify "places only applies to
   positive" semantic.

4. **`places` arg**: `[1, 10]` valid; else `#NUM!`. Verify.

5. **BIN2DEC numeric input**: stringify f64, parse as base-2; if
   any non-binary digit, `#NUM!`. High-bit-set sign-extends.
   - `BIN2DEC(1111111111) = -1` (10 ones → 1023 → -1).
   - `BIN2DEC(1000000000) = -512`.

6. **HEX2DEC / OCT2DEC text input**: 1-arg strict (Microsoft canon;
   tighter than IronCalc's silent 1-2-arg). Length > 10 → `#NUM!`.
   High-bit-set sign-extends to negative decimal.

7. **Round-trip identities**: `bin2dec(dec2bin(x)) = x` for x in
   binary range; same for hex/oct.

### Lexer extension (CROSS-CUTTING)

8. **`letters + digits + letters` → Ident token**: previously
   `DEC2BIN` would lex as `CellRef("DEC2")` + `Ident("BIN")` (DEC2
   interpreted as cell ref column DEC row 2). Now lexes as single
   `Ident("DEC2BIN")`. Verify:
   - Guards: skip if `leading_dollar`/`mid_dollar` set (absolute
     markers would be malformed for both interpretations).
   - Letter prefix non-empty.
   - Trailing letter run accepts alphanumeric + underscore.
9. **Regression risk for existing fns**: `LOG10(2)` previously
   lexed as `CellRef("LOG10")` + `LParen` + `Number(2)` + `RParen`.
   With the new path, `LOG10(2)` still lexes as `CellRef("LOG10")`
   because no LETTERS follow the `10`. Verify no regression for
   trailing-digit-only patterns.
10. **Existing tests**: workspace test passes; this is the strongest
    regression check, but Codex should explicitly verify the lexer's
    test module + any tests covering `letters + digits` patterns
    (LOG10, ATAN2, etc.).
