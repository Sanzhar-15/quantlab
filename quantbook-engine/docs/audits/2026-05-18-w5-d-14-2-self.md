## HIGH findings

### H-1: `sibling_tmp_path` AtomicU64 counter is per-call, defeating dedup

- File: `crates/ql-io-xlsx/src/write/update_original.rs:443-454`
- What's wrong: `let counter = std::sync::atomic::AtomicU64::new(0)` is
  declared inside the function body. Every call gets a fresh
  `AtomicU64(0)` and the `fetch_add(1)` returns `0` every time. The
  unique counter intent doesn't survive across calls.
- Why it matters: two concurrent exports from the same parent
  directory targeting the same output filename would compute the same
  `.{stem}.ql-shadow-{pid}-0.xlsx` shadow path, then race on
  open/write/read. Single-threaded use is fine because pid + counter=0
  is per-process unique vs other tools; the real bug is concurrency
  within ONE Quantbook process.
- Suggested fix: lift the counter to a module-level
  `static SHADOW_COUNTER: AtomicU64 = AtomicU64::new(0);`. Then every
  call increments the shared counter.

### H-2: `<autoFilter ref="...">` overlaps totals row

- File: `crates/ql-io-xlsx/src/write/umya_export.rs:876-879` (inside
  `render_table_xml`).
- What's wrong: when `has_totals` is true, the table's full `ref_a1`
  includes the totals row, but the `<autoFilter ref="...">` uses the
  same full ref. Excel expects the autoFilter range to exclude the
  totals row (the totals row is below the filter, not part of it).
- Why it matters: Excel may render the autoFilter dropdown on the
  totals row cells, and on save may either accept-and-rewrite or
  reject. LibreOffice is generally more lenient. Not catastrophic but
  visibly wrong.
- Suggested fix: when `has_totals`, compute `autofilter_ref` as
  `ref_a1` minus the last row. Trivial helper.

## MEDIUM findings

### M-1: hardcoded `<tableStyleInfo name="TableStyleMedium2"...>`

- File: `crates/ql-io-xlsx/src/write/umya_export.rs:890-892`.
- What's wrong: every exported table gets the `TableStyleMedium2`
  style. If the original xlsx used a different built-in style (or a
  custom one), it's lost on round-trip.
- Why it matters: visual fidelity loss for `UpdateOriginal` workflows.
  `Workbook::tables()` doesn't currently track style names, so this
  is more of a forward-work flag than a defect.
- Suggested fix: extend `TableMetadata` with an optional style name
  field, default to `TableStyleMedium2`, preserve at import. Defer to
  a follow-up batch — out of scope for W5-D-14.2.

### M-2: missing `xl/chartsheets/` and `xl/dialogsheets/` in preserve list

- File: `crates/ql-io-xlsx/src/write/update_original.rs:196-218`
  (`classify_part::preserve_prefixes`).
- What's wrong: chart sheets and dialog sheets are full sheet-class
  parts that the shadow doesn't generate. They're not in the
  preserve_prefixes list, so they fall through to
  `PartAction::DropSilently`.
- Why it matters: any original containing a chart sheet
  (`xl/chartsheets/sheet1.xml`) would lose that sheet on
  `UpdateOriginal` round-trip with no `dropped_features` entry.
- Suggested fix: add `"xl/chartsheets/"`, `"xl/dialogsheets/"`, and
  their rels paths. Also consider adding the workbook.xml reference
  to those sheets — but since shadow's workbook.xml replaces the
  original, the references would be missing. So preservation requires
  both the part AND patching shadow's workbook.xml to include the
  sheet reference. That's a Phase-4.11-followup-sized change.

### M-3: `iterate_simple_self_closing` is a string walker, not an XML parser

- File: `crates/ql-io-xlsx/src/write/update_original.rs:341-378`.
- What's wrong: the parser looks for `<Override` then the next `/>`
  via `text.find("/>")`. If an attribute value contains the literal
  substring `/>` (e.g., `ContentType="text/foo/>"`), the parser
  closes early.
- Why it matters: real-world Content_Types entries are simple
  enough that this doesn't trigger, but a hostile/malformed input
  could produce mismatched results. Belt-and-suspenders: a real
  quick-xml-based parse would be more robust. Acceptable for v1.
- Suggested fix: swap to quick-xml in a follow-up. Module already
  uses zip + manual XML strings; consistency with the
  `read::workbook_xml` parser would be good.

## LOW findings

### L-1: `format_number_literal` outputs "inf" / "-inf" for infinities

- File: `crates/ql-io-xlsx/src/write/umya_export.rs:732-736`.
- What's wrong: if a caller registers
  `NamedTarget::Constant(Value::Number(f64::INFINITY))`, the
  serialized output is `inf` (Rust's f64 Display), which is invalid
  OOXML.
- Why it matters: Quantbook's value-domain doesn't currently produce
  inf as a literal Number. But the path exists.
- Suggested fix: add `n.is_finite()` guard; return `None` for
  non-finite (`Option<String>` already in flight via
  `render_named_target`).

### L-2: quoted sheet names with `''` escape don't round-trip in name targets

- File: `crates/ql-io-xlsx/src/read/names_import.rs:121-138`
  (`split_sheet_ref`).
- What's wrong: a sheet literally named `O'Brien` is stored in OOXML
  as `'O''Brien'!$A$1`. The parser strips the leading `'`, then finds
  the next `'` (which is the first `'` of the `''` pair) and treats
  it as the closing quote. Result: `sheet_name = "O"`, which fails
  the sheet-lookup, fallback to `NamedTarget::Formula`.
- Why it matters: extremely rare in practice. Documented in source
  as a v1 deferred edge case.
- Suggested fix: scan for `''` and translate to `'` after finding the
  closing-quote position via a proper "find unescaped `'`" walker.

### L-3: case-sensitive sheet-name lookup in `register_defined_names`

- File: `crates/ql-io-xlsx/src/read/names_import.rs:32-37`.
- What's wrong: `sheet_lookup` is keyed by exact sheet name. If a
  workbook somehow has a name target referencing a sheet under a
  case-different name, the lookup misses and we fall through to
  Formula.
- Why it matters: OOXML always emits the canonical case-preserved
  sheet name in defined-name targets, so this only matters for
  hand-edited or malformed files. Acceptable.

### L-4: table id 1..N may collide with original table ids on round-trip

- File: `crates/ql-io-xlsx/src/write/umya_export.rs:814`.
- What's wrong: `(1_u32..).zip(...)` assigns sequential ids starting
  at 1. If the workbook was loaded from an xlsx with table ids that
  weren't 1..N (e.g., 5, 7, 12 from a workbook history with deleted
  tables), our export renumbers them.
- Why it matters: external workflows that rely on stable table ids
  across saves (rare) would break. Excel itself reassigns liberally.
- Suggested fix: persist the original table id at import time in
  `TableMetadata` and reuse on export. Phase 4.11 follow-up.

### L-5: shared strings entries from original may go stale in `UpdateOriginal`

- File: `crates/ql-io-xlsx/src/write/update_original.rs` (no direct
  source — by absence).
- What's wrong: `xl/sharedStrings.xml` is owned by the shadow (not in
  preserve_prefixes). If the original had string indexes referenced
  by preserved comment XML or drawing text, those indexes now point
  into a different sharedStrings table.
- Why it matters: comments + drawings typically use inline string
  references, not sharedStrings; the breakage path is narrow. But
  it's a theoretical concern for `xl/printerSettings/`-style parts
  that may reference workbook-global state.
- Suggested fix: out of scope. Document as a v1 limitation.

### L-6: no E2E test for sheet-scoped name round-trip

- File: `crates/ql-io-xlsx/tests/calamine_smoke.rs` (gap).
- What's wrong: `collect_defined_names` serializes sheet-scoped names
  with `localSheetId`, and `register_defined_names` registers them
  via `sheet.set_scoped_name`. But no E2E test exercises this path.
- Why it matters: a regression in the scoped-name path could ship
  without detection.
- Suggested fix: add `w5_d_14_2_round_trip_preserves_sheet_scoped_name`
  test.

### L-7: no E2E test for Strict policy + VBA in UpdateOriginal

- File: `crates/ql-io-xlsx/tests/calamine_smoke.rs` (gap).
- What's wrong: the Strict path
  (`update_original.rs:163-171`) is uncovered by tests. If a future
  refactor changes the error return, no test fails.
- Why it matters: testing-gap risk.
- Suggested fix: add a test with a synthetic xlsx containing a
  vbaProject.bin entry; assert Strict errors out, Permissive
  populates `dropped_features`.

## What looked right

- Cell-fix post-process needles like `<c r="C5" t="str"` correctly
  anchor on the full quoted ref attr, so they don't false-positive on
  cell `AC5` or `C50` (those would have `r="AC5"` / `r="C50"`).
- The `xl/vbaProject.bin` + `xl/activeX/` drops in `classify_part`
  early-return BEFORE the preserve_prefixes loop. The drop is
  reached, and VBA is correctly reported as `UnsupportedFeatureKind::Macros`.
- `<numFmts>` injection inserts before `<fonts>` in styles.xml (right
  after `<styleSheet>` open tag), matching OOXML schema child-order
  requirements.
- `<definedNames>` insertion after `</sheets>` matches OOXML schema
  child-order (sheets before definedNames).
- `inject_table_parts_into_sheet_xml` inserts just before
  `</worksheet>`. OOXML schema allows `<tableParts>` as a late child;
  insertion position is correct.
- `inject_table_rels` and `render_fresh_sheet_rels` both use
  `r:id="rIdT{i+1}"` consistently across the sheet xml and rels file.
  The `T` prefix distinguishes from umya's stock `rId{N}` allocations.
- `xml_attr_escape` correctly handles `& < > " '` → entities.
- `quote_sheet_name` quotes when the name starts with a digit or
  contains non-`[A-Za-z0-9_]` chars. Doubles embedded `'` to `''`.
- `parse_abs_cell` accepts mixed-mode refs (`$A1`, `A$1`, `A1`,
  `$A$1`) by stripping all `$` before splitting at the first digit.
- `ScopedFileGuard` cleanly cleans up the shadow temp file even on
  the error paths (Drop runs unconditionally).
- All 70 ql-io-xlsx tests passing (54 unit + 16 E2E); 4101 workspace
  tests; clippy + fmt + doc all clean.
