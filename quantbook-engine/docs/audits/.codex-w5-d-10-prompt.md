## What to look for

### Correctness

1. **statrs API usage**: `erf(f64) -> f64`, `erfc(f64) -> f64`. Both
   are the pure functions (not distribution-backed). Verify import +
   call sites.

2. **ERF variadic 1-2 args**:
   - 1 arg → `erf(x)`.
   - 2 args → `erf(upper) - erf(lower)` (definite integral from
     lower to upper).
   - Verify the arg-order semantic: IronCalc has `erf(y) - erf(x)`
     where x = args[0], y = args[1]. So with `ERF(lower, upper)`,
     the result is `erf(upper) - erf(lower)`. Our impl: `lower =
     args[0]`, `upper = args[1]`, returns `erf(upper) - erf(lower)`.
     Matches IronCalc.

3. **ERFC strict 1 arg** (IronCalc canon; matches Microsoft).

4. **.PRECISE aliases**: Excel 2010 introduced these for naming
   consistency. ERF.PRECISE is strict 1-arg (Excel canon — PRECISE
   doesn't take 2-arg integral form); ERFC.PRECISE is identical to
   ERFC. Verify the impls match.

5. **`finite_or_num` routing**: all 4 fns route the result. Non-
   finite (NaN/Inf) → `#NUM!`. Verify.

6. **Anchor values** (closed-form reference):
   - `ERF(0) = 0` exact.
   - `ERF(1) ≈ 0.842700792949714869...`.
   - `ERF(2) ≈ 0.995322265018952735...`.
   - `ERF(x) + ERFC(x) = 1` identity across multiple x.
   - `ERFC(0) = 1` exact.
   - `ERF(-x) = -ERF(x)` (odd function).
   - `ERF(x) → 1` as x → ∞.
   - `ERFC(x) → 0` as x → ∞; `ERFC(x) → 2` as x → -∞.

### IronCalc parity

7. Line-by-line vs IronCalc:
   - Arity check (1-2 for ERF; 1-strict for ERFC, ERF.PRECISE,
     ERFC.PRECISE).
   - get_number_no_bools (IronCalc) vs to_number_strict (ours;
     accepts Booleans as 0/1 — documented engine-wide divergence).
   - Direct call to erf/erfc; no domain pre-check (these fns are
     defined for all of f64).

### Risk concerns

- **statrs erf accuracy at extremes**: ERF(5) is documented as
  "approaches 1 to ~12 sig figs". statrs uses Abramowitz-Stegun
  rational approximation; verify accuracy claim matches Excel's
  Cody algorithm (which Microsoft uses).
- **ERFC tail cancellation**: at large positive x, naive
  `1 - erf(x)` would suffer catastrophic cancellation. statrs's
  `erfc` uses a separate rational approximation in that range —
  verify it's correctly stable.
