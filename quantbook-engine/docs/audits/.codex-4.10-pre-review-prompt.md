# Phase 4.10 Function Library Wave 2 — pre-implementation design review

Review the design doc at `docs/architecture/2026-05-16-phase-4.10-function-library-wave-2.md`. This is the pre-implementation review (Phase 4.10.AA equivalent) for the function-library expansion that closes the v1 260-function target.

- Phase 4.8 SHIPPED (structured references + tables, including 4.8.G.3 calcgraph hooks closed 2026-05-16).
- Phase 4.9 SHIPPED (R1C1 + locales + `@`).

## Specific review asks

1. **Open questions § 7** — please answer each:
   1.1. SWITCH type-strictness: IronCalc (strict) vs HyperFormula (coerce). Which does Excel actually do? Read the IronCalc reference at `.references/ironcalc/base/src/functions/logical.rs` or equivalent.
   1.2. Reference-tier value for ISFORMULA / OFFSET / INDIRECT / COLUMN / ROW: should this be bundled with 4.10.D (ISFORMULA only) or broken out as its own design doc? What's the smallest design footprint?
   1.3. OFFSET/INDIRECT: these resolve to runtime ranges. The calcgraph today extracts deps at bind time. Should they be deferred from v1 entirely or shipped with a constrained subset (compile-time-resolvable args)?
   1.4. Financial canon for PMT/FV/PV/NPER/RATE: validate the sign convention + `type` arg (0=end, 1=begin) handling. Reference: `.references/ironcalc/base/src/functions/financial.rs` if present.
   1.5. Wave-2 budget — is 10-12 commits across 2-3 sessions realistic for the proposed scope?

2. **Scope completeness** — are there any v1-target functions in the compat matrix that I missed and should be in Wave 2? Specifically check:
   - The Reserved/Quantbook-specific section (CA/ECHO/FOO are test stubs; SUM.LARGE / etc. — what's real?).
   - The Information section (TYPE, ERROR.TYPE, ISFORMULA — are there others?).
   - Anything tagged `4.10` in the existing matrix.

3. **Batch ordering** — should the batches reorder for risk reduction? My intuition is 4.10.A (logical) → 4.10.B (conditional aggregates) → 4.10.C (`*A` variants) → 4.10.D (info, modulo reference-tier decision) → 4.10.E (math) → 4.10.F (text) → 4.10.G (financial) → 4.10.H (lookup, biggest). Confirm or propose alternative.

4. **Mid-wave audit timing** — the design says "audit after batch D or E". Is that right? Or should we audit at the larger batches (E, G, H)?

5. **Out-of-scope items** — § 2 lists things I'm explicitly deferring. Are any of those wrongly deferred (i.e., should ship in v1)?

6. **Excel canon coverage** — point me at any Excel functions widely used in real workbooks that aren't in the matrix at all and should be.

Report findings as HIGH (design must change before implementation) / MEDIUM (worth a tweak) / LOW (cosmetic / docs). Be terse but specific. If you disagree with my batch breakdown, propose an alternative breakdown explicitly.
