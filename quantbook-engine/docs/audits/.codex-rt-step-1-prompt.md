## What to look for — find these classes of problems

### Architecture

1. **`RefArg` enum** — six variants (Scalar/Range/Reference/Array/Error/Shape). Is every variant reachable from the dispatcher's materializers? Is any variant unused? Could variants be collapsed without losing semantic precision?
2. **`ArgContract`** — two variants today. Does the per-fn `(ReferenceAwareFn, ArgContract)` storage shape scale to per-arg-position contracts (XLOOKUP-style)? Document the scaling path if not.
3. **`PlanKind`** — five variants. Is the mapping from `ExprPlan` variants to `PlanKind` correct for ISREF semantics (i.e., would `ISREF(<any plan>)` return the Excel-canonical TRUE/FALSE)? Verify Binary/Unary collapse to Literal, Array to Literal (ISREF on array literal returns FALSE per IronCalc).
4. **`ReferenceQuery` trait** — does `WorkbookEnv::reference_query() -> &dyn ReferenceQuery` actually compile? Trait-object via `self`? Confirm the dyn-compat impls.

### Binder

5. **`Expr::RangeRef` arm narrowing** — does `resolve_range_ref_to_range` handle all `RangeRef` variants (Cells / WholeColumn / WholeRow / R1C1Cells) correctly? R1C1 is parser-intermediate (rejected); good. But does WholeColumn/WholeRow produce the correct `Range` with `MAX_ROW` / `MAX_COLUMN` bounds?
6. **`BindContext::ReferenceArg` propagation** — when `is_reference_aware_function("ROW")` is true, the arg ctx is `ReferenceArg`. Sub-expressions inside that arg list inherit it. Is that the right shape? Or should each arg position re-derive its context (e.g., `ROW(IF(A1, B1, C1))` — the IF args are scalar-context for IF, but the outer ROW expects a reference)?
7. **`ResolvedName::Range` in `ReferenceArg`** — both `AggregateArg` and `ReferenceArg` produce `ExprPlan::AggregateNameRef`. Is that the right shape, or should `ReferenceArg` produce `ExprPlan::RangeRef { range }` for symmetry with literal ranges?

### Dispatcher

8. **Materializer correctness:**
   - `materialize_ref_arg_eager`: does each ExprPlan variant produce the right `RefArg` variant? Specifically: `ExprPlan::Function { .. }` falls through to `eval_scalar_with_cache` → result wrapped as Scalar/Error. Is that right, or should fn-call args ever produce a Reference (when the called fn returns a reference)? In v1: no reference-returning fns, so always Scalar/Error is correct.
   - `materialize_ref_arg_lazy`: does each ExprPlan variant produce the right `PlanKind`? Specifically: is `Binary { lhs: CellRef, rhs: Number }` Literal (per design § 2.3) or RangeRef?
9. **Cell-boundary multi-cell guard** — at `eval_at_cell_boundary`, the guard fires for ROW/COLUMN with single-arg Range/Array. Is the matching `name.as_ref()` against `"ROW" | "COLUMN"` correct (case-sensitive uppercase)? Are there edge cases (`name.eq_ignore_ascii_case`)?
10. **Dispatcher arm ordering** — `ReferenceAware` arm placed after `Unified`. Is that the right ordering? Could a future name collision masquerade as a different tier?

### Dep walker

11. **`is_dep_suppressed_reference_fn`** — names: ROW/COLUMN/ROWS/COLUMNS/ISREF. ISFORMULA/FORMULATEXT excluded (value-deps as v1 cost). Is the canonical-uppercase check sufficient? What if user calls `=row(A1)` (lowercase)?  The parser canonicalizes to uppercase before binding, so the walker should see `name == "ROW"`. Verify.
12. **`ExprPlan::RangeRef` dep tracking** — synthetic name `"__rt_literal_range__"`. Does the calcgraph stripe-index reverse-lookup correctly with this synthetic name? Could it collide with a user-defined name?

### Env

13. **`CellEnv::reference_query()` default** — returns `&NO_OP_REFERENCE_QUERY`. `MapEnv` inherits. Are there other CellEnv impls in the workspace that should override? Search.
14. **`WorkbookEnv` impl `ReferenceQuery`** — uses `self.workbook.formula_at(...)` and prepends `=`. Is the `=` prepending the right place? What if `formula_at` returns text that already has `=`? (Verify: per `workbook_runtime.rs:573` canonicalization strips `=`.)

### Cross-cutting

15. **No exhaustive matches on `ExprPlan` are unhandled** — verify by grep. Adding a new variant must not break any non-test match.
16. **Plan-cache key** — does adding `ExprPlan::RangeRef` affect plan-cache hashing? Verify.
17. **Op-log replay** — does `WorkbookRuntime::recompute_dirty` correctly evaluate the new `ExprPlan::RangeRef` through `WorkbookEnv::with_formula_cell`? Verify.
18. **Export/import** — qbook round-trip preserves formulas as source text, so `ExprPlan` reconstructs from text via the binder. No serialization change needed; verify nothing depends on direct `ExprPlan` serialization.

### Tests + invariants

19. **`accepts_special_arg_lists_only_registered_aggregates` test** — Step 1 does NOT add the 7 reference-tier names to `is_aggregate_function`, so the test does NOT need extension at Step 1. Verify this — would Step 2 (which registers the fns) break the test if it doesn't add a parallel loop? Recommend a follow-up.
20. **Unit tests in `reference_aware_fns.rs`** — 8 tests. Sufficient? Cover round-trip, duplicate rejection, lowercase rejection. What else should Step 1 ship as a sanity test?

### Documentation

21. **Doc comments** — match the actual behavior? Spot any drift between docs and impl.
22. **Design doc § 5 vs implementation** — does the impl actually match what § 5 says? Any deviations not documented?
