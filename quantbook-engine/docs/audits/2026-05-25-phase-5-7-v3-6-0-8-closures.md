## Findings closed in-cycle (V3.6.0.8.4)

### Convergent HIGHs (both lanes)

**CONVERGENT-HIGH-1 (CODEX-HIGH-2 ≡ OPUS-HIGH-1) — classify_delta_op silently drops metadata ops**.

`classify_delta_op` catch-all arm passed `AddSheet` / `MoveSheet` / `CreateTable` / `DropTable` / `ResizeTable` / `SetName` / `SetLocale` / `SetReferenceMode` / `SetDateSystem` through as cell-only-deltable — IDE saw `fullRebuildRequired=false` + empty `sheets_changed` while the engine had new sheets / tables / settings. Silent data loss class.

**Closure**: replace the `_ => {}` catch-all with an explicit per-variant allowlist that fires `has_rename = true` (force-fullRebuild) on every metadata op. Compiler exhaustiveness check now enforces future Op variants make an explicit delta-surface decision.

Files: `crates/ql-bindings-node/src/lib.rs` `classify_delta_op` lines ~415-444.

### Codex-only HIGHs

**CODEX-HIGH-1 — `poll_remote_with_limit` bypasses workbook-cache invalidation**.

`poll_remote_with_limit` is a 5th log-mutation site (alongside `merge_bytes` / `discard_pending_ops` / `undo` / `redo`) that the V3.6.0.8.2 invalidation discipline missed: remote ops drained via poll can re-order LWW winners or bring rename ops exactly like `merge_bytes`, but the V3.6.0.8.2 wiring left the workbook cache stale after a poll drain.

**Closure**: add `self.force_clear_workbook_cache()` after `self.rebuild_snapshot_cache()?` in the `merged > 0` block, before auto-flush.

Files: `crates/ql-collab/src/session.rs` `poll_remote_with_limit` lines ~3499-3512.

**CODEX-HIGH-3 — snapshot_cells O(N) per delta cell**.

`workbook_snapshot_delta` was calling `snapshot_cells(sheet).into_iter().find(|((r,c),_)| ...)` per changed cell coord; O(cells_in_sheet) per delta cell. At 100k cells × 100 new cells = 10M iterations. Per Codex bench: 746 ms (3× SLOWER than full snapshot).

**Closure**: new `pub fn snapshot_cell(sheet, row, col) -> Option<CellState>` on `CollabSession` (direct `HashMap.get`). Delta path uses this — O(1) amortized per call.

Files: `crates/ql-collab/src/session.rs` `snapshot_cell` ~lines 1986-2014; `crates/ql-bindings-node/src/lib.rs` delta render loop ~lines 2545-2602.

### Opus-only HIGHs

**OPUS-HIGH-2 — no `version` field on `WorkbookSnapshotJson`**.

V3.6.0.8.3 IDE consumer protocol step 2 ("IDE records the `version` returned by workbookSnapshot()") was impossible — no `version` field existed. Mocha tests probed via empty-Buffer `workbookSnapshotDelta` calls; that workaround has a multi-window collab race window.

**Closure**: add `pub version: Buffer` to `WorkbookSnapshotJson` napi struct + IDE `version?: Buffer` interface (TS-side optional for fixture-literal unit tests; napi always populates). Populated in `workbook_snapshot` from `cache_vv.encode()` BEFORE `set_workbook_cache` consumes `cache_vv`.

Files: `crates/ql-bindings-node/src/lib.rs` `WorkbookSnapshotJson` struct + `workbook_snapshot` body; `extensions/quantlab/src/quantbook/types.ts` interface; +2 shape-pinning test updates in mocha.

**OPUS-HIGH-3 — `iter().skip(N)` deserializes ALL N skipped ops**.

The primary performance bug. `inner.log().iter().skip(start).take(end-start)` calls `Iterator::skip` which invokes `next()` N times, deserializing every skipped op. At 100k log + 10 new ops the delta walk paid ~100k unnecessary `serde_json::from_str<Op>` calls. Both the napi delta enumeration AND `apply_ops_in_range` had this.

**Closure**: replace with `for i in start..end { log.get(i)? }` — K * O(log N) BTree random-access (per V3.6.0.X audit-of-D3 closure on `OpLog::get` complexity).

Files: `crates/ql-oplog/src/replay.rs` `apply_ops_in_range`; `crates/ql-bindings-node/src/lib.rs` delta enumeration.
