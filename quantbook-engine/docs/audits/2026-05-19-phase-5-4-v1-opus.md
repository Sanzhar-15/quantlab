## HIGH

**H1 — `op_log().set_peer_id()` silent undo-stack-clear footgun.**
`CollabSession::op_log()` returns `&OpLog`; pre-closure
`OpLog::set_peer_id(&self, ...)` was reachable from `&OpLog`.
Loro's `UndoManager::new` subscribes a peer-id-change callback
that clears both undo + redo stacks on every `set_peer_id` call
(`loro-internal/src/undo.rs:654-662`). So
`session.op_log().set_peer_id(x)` silently nukes the user's undo
history with no visible signal. Fix: change `OpLog::set_peer_id`
to `&mut self`, OR add a runtime guard.

**H2 — `CollabSessionError::Undo(#[from] loro::LoroError)` is
undocumented stability leakage.** The Stability section in
lib.rs:26-31 doesn't list `loro::LoroError` as a re-exported type
callers will see. Loro upgrades can change LoroError variants
and break downstream match patterns. Fix: add a bullet under
`### Pre-stability API changes` warning of the leakage.

## MEDIUM

**M1-M4 — doc drift across `session.rs:7-9`, `crdt-data-model.md:331-344`,
`entry-plan.md:107`, `known-gaps.md:115`** — all describe undo as
future / unpopulated / "removes from log" (the last is factually
wrong: Loro retracts via remote-event composition, doesn't
remove). Fixes: mark V1 SHIPPED + commit hash; correct the
"removes" myth.

**M5 — `add_exclude_origin_prefix` is PREFIX match, not exact.**
Verified at `loro-internal/src/undo.rs:601`:
`event.event_meta.origin.starts_with(&**x)`. With
`PRESENCE_COMMIT_ORIGIN = "presence"`, any future commit starting
with `"presence"` (e.g. `"presence-typing"`) would be silently
excluded. Fix: use a more specific sentinel like `"presence:"`.

**M6 — undo-vs-merge interaction test gap.** No test for: peer A
appends → peer B merges A → A undoes → A re-exports → B merges.
The internal handler (`loro-internal/undo.rs:615-643`) has
non-trivial logic for `EventTriggerKind::Import` (calls
`compose_remote_event` on both stacks). Most novel collab
behavior in 5.4 is unverified.

## LOW

- L1 `clear_undo_stack(&self)` vs `undo/redo(&mut self)` API inconsistency.
- L2 `make_undo_manager` is a free function (acceptable factoring for now).
- L3 No test exercising `Undo(LoroError)` variant (unreachable in V1; document instead).
- L4 Reborn-session undoability not tested (5-line test would pin Loro behavior).
- L5 Peer-id stability warning lives in non-public `undo.rs` docstring; not surfaced to `CollabSession::new` callers.

## Forward implications

- **Phase 5.5 transport:** undo events ARE local-only by Loro's
  contract — they produce inverse ops that subsequently propagate
  via merge path. Worth documenting in 5.5 design.
- **Phase 5.7 IDE:** local-only WILL surprise users ("Ctrl-Z
  didn't undo my teammate's edit"). Surface in user-facing docs early.
