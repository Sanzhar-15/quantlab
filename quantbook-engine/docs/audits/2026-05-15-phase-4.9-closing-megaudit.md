## Findings

### HIGH-1: PlanCache collision for `@<range>` formulas across cells

**File:** `crates/ql-exec/src/workbook_runtime.rs` (4 sites: lines
~605, ~1012, ~3178, ~3326) + `crates/ql-exec/src/plan_cache.rs:60`.

**Issue:** The W5-144 `bind_implicit_intersection` narrows
`@A:A` / `@1:1` / `@A1:A10` etc. AT BIND TIME using `site.cell` per
design § 3.3 — emitting an `ExprPlan::CellRef` that references the
formula's own row/col. The bound plan is cell-specific. But the
`PlanCacheKey` was `(canonical_text, sheet, name_gen)` — no cell
coords. Two `set_formula` calls with `"@A:A"` at different rows in the
same sheet would produce the SAME canonical text → same cache key →
the second call would hit the cache and read the FIRST call's
narrowed coord. Pre-fix regression test:

```rust
// At row 3: @A:A narrows to A4=11 → bound plan reads A4.
let v1 = rt.set_formula(0, 3, 1, "@A:A").unwrap();
// At row 5: cache hit returns the row-3 plan → reads A4 instead of A6.
let v2 = rt.set_formula(0, 5, 1, "@A:A").unwrap();
assert_eq!(v2, Value::Number(99.0));  // pre-fix: FAILS, returns 11
```

**Fix (shipped in this commit, W5-150):** add
`cell_anchor: Option<(RowId, ColId)>` to `PlanCacheKey`. The 4
callers set it to `Some((row, col))` ONLY when canonical text
contains `@` (substring check); `None` otherwise. Non-`@` formulas
keep the cell-independent cache key, preserving the
`SUM(A1:A10)`-across-rows fast path. False positives (`@` inside a
string literal `"@foo"`) cause extra cache-key splits but no
correctness issue. Regression test
`plan_cache_at_range_collision_across_cells_regression` shipped
alongside the fix.

### LOW-1: `LocaleWire::Unknown` round-trip semantics not pinned by test

**File:** `crates/ql-oplog/src/op.rs:296-309` (custom
`Serialize`/`Deserialize`).

**Issue:** The `Serialize` impl for `LocaleWire::Unknown(s)` writes
the original string verbatim — so an op-log file that started with
`locale = "xx"` reads back as `Unknown("xx")` and the next save would
re-emit `"xx"`. That's correct preservation, but no test currently
pins this round-trip. The save-side guard ("never produce Unknown from
runtime") is also not test-pinned.

**Fix (not shipped — LOW):** add a test that constructs
`LocaleWire::Unknown("xx")`, serializes via TOML, deserializes, and
asserts the round-trip. And a test that confirms `from_runtime`
never produces `Unknown`. Both small additions; defer to a follow-up.

### LOW-2: `print_number_with_locale` byte-substitutes `.` in scientific notation safely, but no test pin

**File:** `crates/ql-formula-syntax/src/printer.rs:543-580`.

**Issue:** The locale-aware number printer swaps `.` → locale glyph
in `format!("{n}")` output. Rust's f64 Display emits scientific
notation only for very large / very small magnitudes (≥ 1e16 or with
many fractional digits); within those bounds the `.` is always a
decimal point and the swap is correct. The tests cover
`0.00001` (DE → `0,00001`) and `1e10` (integer-valued — no `.`,
swap is no-op). Not tested: a true scientific output like `1.5e-30`
(Rust may print as `1.5e-30`; locale swap would produce
`1,5e-30`). That's actually correct behavior — only the decimal
separator changes, the `e` stays — but no test pins it.

**Fix (not shipped — LOW):** add a test for a magnitude that
forces scientific notation. Or document that the swap explicitly
preserves `e` (in the docstring).

### LOW-3: AxisSpec::Rel(i32::MIN) edge-case not test-pinned, but arithmetic is correct

**File:** `crates/ql-exec/src/plan.rs:1083-1116`.

**Issue:** `resolve_r1c1_axis` computes `anchor as i64 + offset as i64`
and bounds-checks `resolved < 0 || resolved > bound`. For
`AxisSpec::Rel(i32::MIN)` (-2,147,483,648), the i64 sum is far
negative → bound check catches it → `R1C1OutOfBounds`. No overflow
risk. Verified by reading the code. The existing tests cover
`R[-1]` and `R[1]` overflow but not `i32::MIN`/`i32::MAX` extremes.

**Fix (not shipped — LOW):** add edge-case tests at `i32::MIN` and
`i32::MAX`. Defer to a follow-up.

## Areas verified clean

- **Two-phase load (qbook v7, W5-145):** the `SchemaVersionProbe`
  pattern works as documented. `SchemaVersionProbe` has no
  `deny_unknown_fields`, so a v8+ file passes phase 1 with all its
  unknown fields tolerated, then the version-range check fires and
  returns `UnsupportedSchema { found: 8 }` before serde tries the
  full envelope.

- **Locale `Unknown` propagation (W5-145 + W5-146):** load-side
  surfaces `QbookError::UnknownLocale`, op-log replay surfaces
  `ReplayError::UnknownLocale`. Save-side guards: `from_runtime` only
  emits canonical variants. No save-side path can produce `Unknown`
  from a runtime `Locale`.

- **`@` operator fingerprint stability (W5-143):** tag byte 13 is
  free of collisions (Number=0, String=1, Bool=2, CellRef=3,
  RangeRef=4, Binary=5, Unary=6, Function=7, Array=8, Spill=9,
  NameRef=10, Error=11, StructuredRef=12, ImplicitIntersection=13).

- **R1C1Ref / R1C1Cells `unreachable!()` arms (W5-139):** verified by
  inspecting `set_formula`'s canonicalization flow. Per design § 4.4,
  canonical text is ALWAYS A1+EnUs; the intermediate forms get lowered
  before reaching fingerprint / stripe registration. No production
  path exposes the panic.

- **Mode/locale change leaves stored text canonical (W5-148):** verified
  by `reference_mode_change_leaves_stored_formula_text_canonical` and
  `locale_change_leaves_stored_formula_text_canonical` tests.

- **`Sales[@Col]` vs `@Sales[Qty]` AST disambiguation (W5-148):**
  both evaluate identically via the existing `is_this_row: true`
  narrowing path. Verified by
  `structured_ref_at_inside_vs_outside_brackets_eval_identically`.
