## HIGH

### HIGH-1 -- `undo()` / `redo()` bypass `last_snapshot` invalidation

**Files:**
- `crates/ql-collab/src/session.rs:1799-1853`
- `crates/ql-collab/src/session.rs:2695-2716`
- `crates/ql-collab/src/session.rs:692-700`

**Problem:** V3.3.0.3 documents and implements cache maintenance for the explicit append/merge/import/discard/poll paths, but `undo()` and `redo()` are existing public engine mutators that change the visible `"ops"` LoroList through `UndoManager`. The regression test `undo_retracts_visible_op_from_op_log_len` confirms that a consumed undo shrinks `op_log().iter().count()` and `op_count()` (`crates/ql-collab/src/session.rs:2695-2716`). Neither `undo()` nor `redo()` calls `rebuild_snapshot_cache()` before returning (`:1822-1853`).

**Reproduction:**
1. Create a `CollabSession`.
2. Append two `Op::PutValue` cells on sheet 0, including one at `(0, 1)`.
3. Call `snapshot_cells(0)` and observe both cells.
4. Call `undo()`. The visible op log retracts the last op.
5. Call `snapshot_cells(0)` again. The stale `last_snapshot` still contains the undone cell because the cache was not rebuilt.

The same issue affects redo in the opposite direction if the cache had been corrected by another path between undo and redo.

**Impact:** Public Rust engine snapshot reads can return cells that are no longer present in the visible op log after undo, or omit restored cells after redo. The current V3.3 IDE path does not expose undo/redo through napi, so this is not on the shipped cell-grid UI path, but it violates the V3.3 cache correctness contract and is load-bearing for V3.4 undo work.

**Suggested closure:** In both methods, when `consumed == true`, call `self.rebuild_snapshot_cache()?` before `maybe_auto_flush()`. Add ql-collab tests that assert `snapshot_cells` and `exportSnapshot` semantics across undo and redo for distinct cells and same-cell LWW overwrites.

## MEDIUM

### MEDIUM-1 -- `rebuild_snapshot_cache()` clears the valid cache before fallible iteration

**File:** `crates/ql-collab/src/session.rs:725-733`

**Problem:** `rebuild_snapshot_cache()` calls `self.last_snapshot.clear()` and then walks `self.log.iter()`. If `iter()` returns a decode/schema error mid-walk, the method returns `Err` with `last_snapshot` left empty or partially rebuilt.

**Reproduction:** Corrupt the `"ops"` LoroList so that one entry before the end is not a valid serialized `Op`, then call any full-rebuild path such as `merge_bytes`, `from_snapshot`, `discard_pending_ops`, or `poll_remote_with_limit`. The method returns an error, but subsequent `snapshot_cells()` reads observe the partially rebuilt cache.

**Impact:** This requires corrupt or incompatible op-log contents, so it is not a normal V3.3 path. It does, however, weaken the error contract: after a failed rebuild, the session contains mutated state plus a partially invalidated read cache.

**Suggested closure:** Build into a local `HashMap`, return on iteration error without touching the existing cache, and assign `self.last_snapshot = rebuilt` only after the full walk succeeds. If the intended contract is "failed rebuild invalidates all snapshot reads", add an explicit poisoned-cache state instead of leaving a partial map.

### MEDIUM-2 -- Panel title computation silently swallows `listSheets()` errors

**File:** `extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:155-166`

**Problem:** `CellGridPanel.show()` catches all exceptions from `session.listSheets().length` and silently falls back to no title suffix. `listSheets()` errors represent op-log iterator failures surfaced as `[bad_argument]` at the napi layer (`crates/ql-bindings-node/src/lib.rs:591-594`), so swallowing them hides a real session integrity problem.

**Reproduction:** Make `session.listSheets()` throw, then call `CellGridPanel.show(...)`. The panel title becomes `Cell Grid (Sheet N)` and no output-channel line, warning, or error message records the failure.

**Impact:** This does not corrupt cell data, but it violates the repository's general "no silent fallback" error discipline and makes corrupt sessions harder to diagnose.

**Suggested closure:** Replace the empty catch with an observable diagnostic. A low-noise option is to log to the Quantlab output channel and keep the no-suffix fallback; a stricter option is to surface the error and abort panel creation.

## LOW

### LOW-1 -- V3.3 docs and title comments overstate listSheets/exportSnapshot cache costs

**Files:**
- `docs/architecture/ide-consumer-contract.md:622`
- `docs/architecture/ide-consumer-contract.md:653-655`
- `docs/architecture/ide-consumer-contract.md:748`
- `extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:155-160`
- `crates/ql-bindings-node/src/lib.rs:587-603`
- `crates/ql-collab/src/session.rs:671-700`

**Problem:** The shipped contract says `listSheets` reads from the incremental snapshot cache after V3.3.0.3 and that export snapshot is O(cells-on-sheet). Source says otherwise. `listSheets()` still scans the op log into a `BTreeSet` (`crates/ql-bindings-node/src/lib.rs:587-603`). `snapshot_cells()` scans all cached cells and filters by sheet, so it is O(cells-in-cache), not O(cells-on-sheet) (`crates/ql-collab/src/session.rs:671-700`).

**Reproduction:** Compare the docs/comment lines above with the source implementation. There is no runtime failure; this is documentation drift.

**Suggested closure:** Update `ide-consumer-contract.md` and the title comment to say:
- `listSheets()` is O(op count), sorted/deduped via `BTreeSet`, and currently not cache-backed.
- `exportSnapshot` lock-hold time is O(total cached cells) with a sheet-filter pass; V3.x may nest by sheet for O(cells-on-sheet).
- The one title call per `show()` remains bounded by user action, but not by distinct sheet count.

### LOW-2 -- Switch-sheet inline comment contradicts the actual oldest-panel semantic

**File:** `extensions/quantlab/src/commands/quantbookCommands.ts:273-299`

**Problem:** The main V3.3.0.5 comment correctly says `panels[0]` is the oldest open local panel by V8 `Map` insertion order (`:273-284`). A later inline comment says the first panel is "presumed most-recently focused / least surprising" (`:294-298`), which is false for the implementation.

**Reproduction:** Open two local cell-grid panels from different sessions. `CellGridPanel.activeLocalPanels()` iterates `localPanels.values()` insertion-order (`extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:272-278`), and the command selects `panels[0]`, the oldest.

**Suggested closure:** Replace the inline comment with "oldest open local panel; V3.x can add a panel picker or active-panel tracking".

### LOW-3 -- Virtualized row rendering leaves row/col attributes unescaped

**File:** `extensions/quantlab/src/quantbook/cellGrid/cellGridHtml.ts:197-201` and `:438-450`

**Problem:** `valueStr` and `kind` are escaped in both server and client row renderers, but `e.row` and `e.col` are interpolated directly into text and `data-row` / `data-col` attributes. Current engine and TypeScript types make them numbers, so normal V3.3 data cannot inject HTML. The literal claim that all attribute values are escaped is still false.

**Reproduction:** Forge a `QuantbookCellSnapshot` in a test with `row` cast to a string containing a quote and event handler, then call `buildHtml(...)` or let the client renderer consume a tampered `cell-grid-data` block. The raw row/col value reaches the attribute string.

**Suggested closure:** In both renderers, normalize and escape row/col before interpolation:
`const row = escapeHtml(String(e.row)); const col = escapeHtml(String(e.col));`
for server rendering and equivalent `htmlEscape(String(e.row))` / `htmlEscape(String(e.col))` in the client mirror. Add a defense-in-depth test.

## Out of scope (deferred to V3.x)

- **Nested `Op::BatchCommit` `PutValue` support.** `Op::BatchCommit { ops: Vec<Op> }` can contain nested `PutValue` operations (`crates/ql-oplog/src/op.rs:168-176`), but the V3.3 cache/listSheets paths only match top-level `Op::PutValue` (`crates/ql-collab/src/session.rs:578-580`, `:729-730`; `crates/ql-bindings-node/src/lib.rs:595-596`). V3.3 napi only appends top-level `PutValue`, so this is not load-bearing for the shipped grid. Full Op enum routing or rebuild-workbook-backed grid reads must recurse or explicitly reject nested cell writes.

- **Tombstoned or metadata-only sheets.** `listSheets()` enumerates sheets only from visible `PutValue` ops, and `snapshot_cells(sheet)` returns empty when no cached cell remains. Future `SheetMetadata`, hidden sheets, empty sheets, and undo/tombstone semantics need a separate metadata API and cache invalidation plan.

- **DOM/webview integration test.** The V3.3.0.6 pure-helper tests cover geometry and HTML-string invariants without jsdom. A true DOM test that executes the scroll handler inside a document is still useful, but accepting the jsdom deferral is reasonable for V3.3 (`docs/architecture/ide-consumer-contract.md:763-764`).

- **Half-row scroll boundary tests.** The implementation handles `scrollTop = rowHeight - 1` and `scrollTop = rowHeight` correctly through `Math.floor`, but the new scroll-simulation test only checks exact row-height increments (`extensions/quantlab/test/quantbook-roundtrip.test.ts:3180-3196`). Add half-row fixtures if virtualization churn continues.

- **Scroll throttling for larger V3.x grids.** The current unthrottled scroll listener repaints on each scroll event (`extensions/quantlab/src/quantbook/cellGrid/cellGridHtml.ts:480-484`). At V3.3 scale this is acceptable; larger WAN-scale or 10k+ row views may need `requestAnimationFrame` coalescing.

- **Reactive title updates.** Panel title suffixes are point-in-time by design (`extensions/quantlab/src/quantbook/cellGrid/cellGridPanel.ts:146-166`). Later appends or remote merges that create sheets do not update existing titles until another `show()` call.
