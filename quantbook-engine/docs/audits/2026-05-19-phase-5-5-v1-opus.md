# Opus audit — Phase 5.5 V1 (LoopbackTransport) 2026-05-19

Auditor: Opus subagent.
HEAD audited: `924750819bc` (truncation-fix on `3590aa6d89e` Phase 5.5 V1).
Total: 66,990 tokens / 14 tool uses / 108s wall.

## HIGH

**H1 — `pair()` close semantics: A.close orphans bytes in A's INBOX**
Test comment in `loopback_close_one_side_does_not_affect_peer` was
backwards. Pre-closure, A.close blocks BOTH a.send and a.try_recv,
so already-queued bytes in A's inbox are unreachable. The trait
docstring at transport.rs:41-46 promises drain-before-Closed.

**H2 — `pending_recv()` ignores the closed flag** (transport.rs:226-228).
Tests + Debug read inbox size unconditionally. Inconsistent with
`try_recv` returning `Closed` immediately. Either document the
diagnostic-only gap or gate on `!is_closed()`.

## MEDIUM

**M1 — No `Send + Sync` static assertion despite doc claim**
(transport.rs:135-136). Add `const _: fn() = ...` block to pin
the contract at compile time.

**M2 — `AtomicBool::Relaxed` cross-thread ordering not guaranteed**.
Cross-thread "close-then-send" race can observe stale `closed=false`
and enqueue bytes after close. For loopback (single-process test
harness) this is almost certainly fine, but the docstring promises
cross-thread safety. Either document the caveat or use stronger
ordering.

**M3 — Mutex poison → `TransportError::Io`** violates the
no-fallbacks rule from CLAUDE.md (errors must be VISIBLE; poison
is a panic-origin signal, not I/O). Either panic on poison
(`lock().unwrap()`) or add a `Poisoned` variant.

**M4-M7 — Doc drift across 5 files** (crdt-data-model.md,
entry-plan.md, known-gaps.md, session.rs, transport.rs) — all
describe 5.5 as future / Noop-only.

## LOW

- L1: No multi-threaded test verifying Send+Sync at runtime.
- L2: No large-blob (1MB) test.
- L3: No "B sends after A closes; assert bytes are queued but A
  cannot drain" pinning test (overlaps with H1 closure).
- L4: No "close mid-exchange" integration test.
- L5: `close(&self)` vs `send(&mut self)` API inconsistency
  (defensible, but worth a doc comment).
- L6: `loopback_close_one_side_does_not_affect_peer` test comment
  inaccurate (closed by H1).

## Forward implications

**F1. Transport trait sync vs async.** Current send/try_recv are
sync. WebSocket impl on tokio will want async. Discuss before V2:
make Transport async (breaking) OR add separate AsyncTransport.

**F2. Framing.** Trait says framing is impl-responsibility.
WebSocket gives message framing free; raw TCP/QUIC needs
length-prefixing.

## Verdict

**7 SHOULD-FIX (2 HIGH + 7 MEDIUM as cluster + 6 LOW).**
No MUST-FIX — no soundness violations, no test failures, no API
breaks. Send+Sync doc claim (M1) is closest to MUST since
unverified public contract.

## Closure (post-audit)

- H1+H2: drain-before-Closed semantic implemented in
  `LoopbackTransport::try_recv`. Test updated + renamed
  `loopback_close_blocks_send_but_drains_recv`. Trait contract
  now matches V1 behavior.
- M1: Send+Sync static assertion added via `const _: fn() = ...`.
- M2: Documented atomic-ordering caveat in LoopbackTransport docstring.
- M3: KEPT — Io semantic acceptable per Codex's PASS; Opus's
  poison-panic alternative would force callers to handle a
  panic-origin error mid-call, not improving on the Io mapping.
- M4-M7: Doc drift closed across all 5 files.
- L1-L5: Deferred per stated rationale (compile-time assertion
  M1 covers the Send+Sync claim; large-blob test not needed for
  pass-through impl; L4 valuable but not blocking V1; L5
  documented).
