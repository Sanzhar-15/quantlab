## What to look for

### Correctness (highest priority)

1. **XNPV math kernel**:
   - `xnpv = v[0] + Σᵢ₌₁ⁿ⁻¹ vᵢ / (1 + rate)^((dᵢ - d₀)/365)`.
   - Verify the i=0 term (`v[0]` unscaled — first cash flow is at
     d₀ so no discount).
   - Verify `.powf((d-d₀)/365.0)` matches IronCalc exactly.
2. **XNPV derivative for Newton-Raphson**:
   - `d/dr xnpv = -Σᵢ₌₁ⁿ⁻¹ vᵢ · (ratio) / (1+r)^(ratio+1)` where
     `ratio = (dᵢ-d₀)/365`.
   - Verify the i=0 term doesn't contribute (its discount factor is
     1, no derivative term).
3. **XIRR algorithm**:
   - Newton-Raphson from guess (up to 100 iterations, eps=1e-7).
   - Fallback to bisection on `[-0.9999, 100]`.
   - If `f(-0.9999) * f(100) > 0` (no sign change), try Newton-Raphson
     from guess=200 (catches roots above 100).
   - Bisection: 50 iterations, eps=1e-8.
   - Verify each step matches IronCalc.
4. **XIRR sign-change requirement**: at least one positive AND one
   negative value (else `#NUM!`).
5. **XIRR guess <= -1.0 → `#VALUE!`** (matches IronCalc).

### Domain checks

6. **XNPV strict 3 args** (Microsoft canon). IronCalc has a bug
   accepting 2 args but then crashing on `args[2]`; we require
   strictly 3. Verify.
7. **XIRR 2-3 args** (guess optional, default 0.1).
8. **XNPV `rate > 0` STRICT** (matches IronCalc).
9. **Length mismatch values vs dates → `#NUM!`**.
10. **Date < first_date → `#NUM!`**.
11. **Date outside Excel serial range `[0, 2_958_465]` → `#NUM!`**.
    Note: IronCalc uses `MINIMUM_DATE_SERIAL_NUMBER` /
    `MAXIMUM_DATE_SERIAL_NUMBER`; we use 0 and 2_958_465. Verify
    the bounds match Excel's 1900-01-00 to 9999-12-31 calendar.

### XNPV vs XIRR cell-collection divergence

12. **XNPV `collect_xnpv_range`**: rejects empty + non-numeric +
    text + bool with `#NUM!`. Errors propagate.
13. **XIRR `collect_xirr_range`**: empty cells → 0.0; non-numeric
    text/bool → `#VALUE!`. Errors propagate.
