## What to look for

### Correctness (highest priority)

1. **statrs API verification:** `Binomial::new(p, n: u64)`,
   `NegativeBinomial::new(r: f64, p)`, `Poisson::new(lambda)`,
   `LogNormal::new(mean, sd)`. Trait methods (PMF for discrete, PDF
   for continuous, CDF, inverse_cdf). EXPON.DIST closed-form.
2. **u64 conversion safety** for discrete-distribution observation
   indices: `to_u64_index(v)` — verify pre-checks `>= 0.0`,
   `<= u64::MAX as f64`, NaN-reject, before the `as u64` cast.
3. **`BINOM.INV` `p == 0.0` special case**: statrs's default
   `DiscreteCDF::inverse_cdf` calls `integral_bisection_search` which
   returns `None` for degenerate (constant-CDF) distributions, then
   `.unwrap()` panics. The impl short-circuits with `Value::number
   (0.0)` before constructing the dist. Verify this is correct and
   documented.
4. **`POISSON.DIST` `lambda == 0.0` special case**: `Poisson::new
   (0.0)` rejects. Impl handles inline (`P(X=0)=1`, `P(X>0)=0`,
   `CDF=1` for any k≥0). Verify.
5. **Domain checks match IronCalc canon line-by-line:**
   - BINOM.DIST: `number_s.trunc()` in `[0, trials]`, `0 <= p <= 1`
     inclusive, 4 args.
   - BINOM.DIST.RANGE: **VARIADIC 3-4 args**, `number_s <= number_s2
     <= trials`, `0 <= p <= 1`. 3-arg form defaults `number_s2 =
     number_s` (single point).
   - BINOM.INV: `0 <= p < 1` STRICT upper, `0 < alpha < 1` strict
     both. (Diverges from BINOM.DIST inclusive.)
   - NEGBINOM.DIST: `failures >= 0`, `successes >= 1`, `0 < p < 1`
     strict both. statrs `NegativeBinomial::new(successes, p)`.
   - POISSON.DIST: `x >= 0` (truncated to u64), `mean >= 0` (NOT
     strict; mean=0 is the special case).
   - EXPON.DIST: `x >= 0`, `lambda > 0` STRICT.
   - LOGNORM.DIST: `x > 0` STRICT, `sd > 0` strict. `mean` may be
     negative.
   - LOGNORM.INV: `0 < p < 1` strict both, `sd > 0`.
6. **`.expect()` justifications** for `binomial_with`,
   `negative_binomial_with`, `poisson_with`, `log_normal_with`:
   pre-check + `to_number_strict`'s NaN rejection make constructor
   failure unreachable. Verify the chain holds.
7. **`finite_or_num` routing**: BINOM.DIST / BINOM.DIST.RANGE /
   NEGBINOM.DIST / POISSON.DIST / EXPON.DIST / LOGNORM.DIST /
   LOGNORM.INV all route through `finite_or_num`. BINOM.INV returns
   `Value::number(k as f64)` directly since the result is a u64 cast
   (no Inf/NaN possible).
8. **Anchor values closed-form:**
   - BINOM.DIST: pmf(k=5; n=10, p=0.5) = C(10,5)/1024 = 252/1024.
   - NEGBINOM.DIST: pmf(0; r=1, p=0.5) = p^1 = 0.5.
   - POISSON.DIST: pmf(0; λ=1) = e^-1.
   - EXPON.DIST: CDF(1; λ=1) = 1 - e^-1, PDF(1; λ=1) = e^-1.
   - LOGNORM.DIST: CDF(1; μ=0, σ=1) = Φ(0) = 0.5; PDF(1; μ=0, σ=1) =
     1/√(2π).
   - LOGNORM.INV: LOGNORM.INV(0.5; μ, σ) = exp(μ) (median).

### Variadic handling (BINOM.DIST.RANGE)

9. **Arity range check**: `!(3..=4).contains(&args.len())`. Verify
   inclusive both ends.
10. **3-arg default**: `number_s2 = number_s` when only 3 args.
    Returns `pmf(number_s)` effectively (lower == upper).
11. **`lower == 0` short-circuit**: avoids u64 underflow when
    computing `cdf(0 - 1)`. Verify the impl has this branch.

### IronCalc divergences

12. Same coercion divergences as prior batches (`to_number_strict`
    accepts Boolean → 0/1; IronCalc rejects via `get_number_no_bools`
    for POISSON/EXPON/LOGNORM but accepts via `get_number` for BINOM).
13. **BINOM.INV `p=0` special-case**: IronCalc would also panic here
    (uses same statrs); we surface a correct value via inline handling.
    Document as IronCalc-divergent-but-mathematically-correct.
