# Quantlab Bug Fix Plan - 2026-01-26

## Issue 1: Chart Drag Instability (CRITICAL)

### Problem Description
When dragging the chart:
- The graph zooms out to one point
- Only the grid moves normally
- Resets to normal after dragging the axes

This regression appeared recently during strategy signal optimization.

### Root Cause Analysis

#### Primary Cause: Visible Range Collapse

**Location**: `Charts/packages/chart-render-canvas2d/src/index.ts:7279-7281`

```typescript
const timeSpan = range.to - range.from;
const timeScaleX = timeSpan > 0 ? plotRect.width / timeSpan : 0;  // BECOMES 0!
const timeOriginX = plotRect.x - range.from * timeScaleX + xOffset;
```

When `timeSpan` becomes 0 or near-zero:
- `timeScaleX` becomes 0
- ALL candles render at the same X position (`timeOriginX`)
- Grid continues working because it uses pixel offsets, not scale multiplication

#### Secondary Cause: Grid vs Series Rendering Asymmetry

**Grid rendering** (lines 6462-6512):
```typescript
const gridXTicks = panOffsetPx !== 0
  ? xTicks.map((tick) => ({ ...tick, px: tick.px + panOffsetPx }))
  : xTicks;
```
Grid applies `panOffsetPx` as a VISUAL OFFSET to tick pixel positions.

**Series rendering** (lines 8091, 8251-8260):
```typescript
const range = xScale.getVisibleRange();  // Gets raw range
// ...
renderSeriesToContext(
  seriesCtx, seriesLayer, paneState.plotRect,
  range,        // <-- UNMODIFIED visible range
  paneSeries, range,
  undefined, panOffsetPx  // <-- Offset passed separately
);
```
Series use `xScale.getVisibleRange()` which may return collapsed/invalid range.

### Investigation Steps

#### Step 1: Add Diagnostic Logging
Add to `renderSeriesToContext` (line 7279):
```typescript
const timeSpan = range.to - range.from;
if (timeSpan <= 0) {
  console.error('[CHART BUG] Range collapsed!', { from: range.from, to: range.to, timeSpan });
}
```

#### Step 2: Trace Range Through Pan
Log in these locations:
- `applyPanDelta()` (line 4540) - before/after `xScale.panByPixels()`
- `renderSeries()` (line 8091) - when range is read
- Compare values between grid and series rendering

#### Step 3: Check Time Scale State
Review `TimeScale.panByPixels()` in `chart-core/src/time-scale.ts:599`:
```typescript
public panByPixels(deltaX: number): void {
  const span = this._visible.to - this._visible.from;
  if (span <= 0) return;  // Early return if collapsed
  // ...
}
```

#### Step 4: Git Bisect
Find the breaking commit by bisecting recent changes to:
- `index.ts` in chart-render-canvas2d
- Signal/marker optimization changes
- Any pan-related modifications

### Potential Fixes

#### Fix A: Range Guard in Series Rendering
```typescript
// Before line 7279
if (range.to <= range.from) {
```

#### Fix B: Ensure Range Consistency
Verify that `xScale` state is consistent between:
1. Grid tick generation
2. Series rendering
3. Plugin state building

#### Fix C: Review Recent Signal Optimization
Check what changed in the signal optimization that might affect:
- Visible range calculation

## Issue 2: Linux Taskbar Icon Disappeared

### Current State
- **Desktop file**: `~/.local/share/applications/quantlab-dev.desktop` ✓ EXISTS
- **Icon path**: `/home/steppen0mad/Desktop/quantlab/quantlab/resources/linux/quantlab.png` ✓ EXISTS
- **Icon format**: PNG 512x512, 8-bit RGBA ✓ VALID

### Likely Causes

1. **Desktop database not refreshed** - Most common cause
2. **Icon cache needs clearing** - GNOME/KDE cache icons
3. **StartupWMClass mismatch** - Window class doesn't match desktop entry

### Fix Steps

#### Step 1: Refresh Desktop Database
```bash
update-desktop-database ~/.local/share/applications/
```

#### Step 2: Clear Icon Cache
```bash
# For GNOME
rm -rf ~/.cache/icon-cache.kcache
gtk-update-icon-cache ~/.local/share/icons/ 2>/dev/null

# For KDE
kbuildsycoca5 --noincremental
```

#### Step 3: Verify StartupWMClass
Run quantlab and check actual window class:
```bash
xprop | grep WM_CLASS
# Click on quantlab window
# Should output: WM_CLASS(STRING) = "quantlab", "Quantlab"
```

Update desktop file if needed:
```ini
StartupWMClass=quantlab  # or whatever xprop shows
```

#### Step 4: Copy Icon to System Location (if needed)
```bash
mkdir -p ~/.local/share/icons/hicolor/512x512/apps/
cp /home/steppen0mad/Desktop/quantlab/quantlab/resources/linux/quantlab.png \
   ~/.local/share/icons/hicolor/512x512/apps/quantlab.png
gtk-update-icon-cache ~/.local/share/icons/hicolor/
```

#### Step 5: Restart Desktop Environment
```bash
# For GNOME
killall -3 gnome-shell

# Or log out and back in
```

### Verification

1. Open application menu - quantlab icon should appear
2. Pin to taskbar - icon should display
3. Run quantlab - taskbar icon should show while running
