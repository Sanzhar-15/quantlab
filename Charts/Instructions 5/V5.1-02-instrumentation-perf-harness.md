# V5.1 Prompt 02 - Instrumentation + Perf Harness Metrics

Goal
- Extend instrumentation so all V5.1+ improvements are measurable and comparable.

Constraints
- Additive-only debug APIs.
- No changes to user-facing API.
- Perf JSON shape must remain backward compatible with existing baselines.

Deliverables
- Extend debug API output in `packages/chart-render-canvas2d/src/index.ts`.
- Extend perf harness metrics output in `apps/perf-harness`.
- Document new metrics fields in perf docs if needed.

Steps
1) Extend debug API:
   - Add memory sampling stats (heap + working set) if available.
   - Add LOD work per frame + worker queue depth fields.
   - Ensure all new fields are optional and don’t break existing consumers.
2) Extend perf harness:
   - Record EventTiming input latency when supported.
   - Record memory stats in perf JSON output.
   - Include environment metadata (DPR/locale/timezone/CPU class).
3) Maintain perf JSON schema stability:
   - New fields must be optional.
   - Baseline loading must not fail if fields are missing.
4) Update perf docs only if new fields need to be interpreted by humans.

Acceptance
- Perf harness output includes new metrics when supported.
- Baselines load without errors.
- Existing A/B/C scenario outputs unchanged aside from optional fields.

Tests
- Run perf harness locally with `PERF_SKIP_COMPARE=1` and confirm metrics populate.
